## 输入与事实

源场景为 world-building 制作的细胞传代黑灯实验室，Panda 七轴机械臂安装在 2.95m 线性滑轨上，采用偏置宽夹指。完整装配视觉保存在 render_scene_lookdev.blend；lab_visual.glb 只是自制物件的局部派生物，而且 glTF 为 Y-up，不能直接视为平台完整 Z-up 场景。

源物理为 MuJoCo 3.17.0 的 MJCF：59 bodies（含world）、3256 geoms、43 joints、24 actuators、18 equalities、3 tendons、0 mocap；仅做 compile/forward，没有运行仿真。原项目的成功是脚本驱动的 MuJoCo 运行和 Blender 姿态回放，尚无本平台或 Claude 的成功结果。

平台保持 USD 为规范格式，Newton 为物理事实源；现有 add_mjcf 辅助函数不等于外部 MJCF 包可公开导入。现有 robot-arm/v1 是七个弧度关节，不能将滑轨米制坐标塞进第八个角度。新增能力需显式建模滑轨、宽夹爪、设备执行器和物料状态；行为仍留 devices YAML 与 packages/programs，通过统一 action pipeline。

## 建议的交付阶段

1. 本地视觉素材/场景入库：完整装配导出、输入/坐标/许可/哈希冻结，通过现有导入和验证入口可浏览、启动。保留可复用素材版本，明确只建立视觉资格。
2. 最小物理见证：Panda/滑轨、母板/盖、培养箱与观察站的 USD/Newton 对应。先验证真实支撑、夹取、移动、稳定落放、门/抽屉联锁，避免在失败的抓取基础上扩展全流程。
3. 设备与物料：移液站/吸头、开盖器/管盖、离心机/配平、计数与废物；离心机保留八孔外观，但只有源物理已支持的2/6两个相对装载位获得资格。把源项目允许的局部理想化显式记录为设备能力与结果，不靠回放、瞬移或外部写状态完成。
4. 完整14步 Operation Plan，独立状态/接触/库存核验、原有拒绝与恢复场景，再执行 Windows Claude 默认模型的真实 MCP-only 实验。
5. 通过适用回归、Newton CPU四项、独立审查及准确候选 CI 后集成。教程与视频只写实际已验证结论；失败进入 issue 修复，不剪成成功。

## 首个独立物理见证

完整视觉输入固定为最终lookdev场景评估后的frame0；不用当前帧或旧render_scene的末尾采样姿态。独立解码GLB、核对源对象清单与世界包围盒，不能只依赖导出器自报的期望值。

USD→Newton首先核对实际body/site初始姿态、质量/惯量、轴与限位及接触排除，滑轨+X/0..2.95m、Panda基座Z=.85m、工作站A/C支撑Z=.914m、管座Z=.919m、培养箱底座Z=.4m为源参数见证。未经对应的参数/特性列出缺口。

最早动态门槛为培养箱→母板取出→观察站放入/收回/观察。通过公开动作与Operation Plan驱动，验证实际接触支撑、稳定放置、目标占用、门/抽屉联锁和录制回放；不能通过直接设置qpos、回放npz或程序外改物料状态获得成功。

## 必须保持的保真度与结论边界

- 板、盖、门、抽屉与离心机盖采用真实支撑/接触；检查穿透、禁止接触、滑移与落放稳定。不能使用跟随约束伪造支撑。
- 源项目允许小管/管盖/吸头在几何对准合格后用约束连接，标为理想化；不扩大至大件搬运。
- 液体、细胞数与谱系采用明确的符号模型，观察/计数为模拟数据；不宣传真实生物学实验或已训练策略。
- 解离和离心沿用教学时长并在 UI/教程/视频标注；不能把剪辑加速混同于实验定义。
- Claude 使用已安装 Windows 2.1.318，保留用户默认模型，记录响应中观察到的模型（未返回则记未知）。隔离的空工作区只提供平台工具与当前 lab-operate skill；无原轨迹、解答脚本或直接源码状态写权限。
- 先做120秒内的连接/观察小样，再做1800秒内的完整演示；每次运行记录预算与使用量，遇到重复提供方故障且无业务调用时停止消耗并修复环境。
- 成功必须由 Plan、每次 invocation、独立物理与最终状态、完成且可回放的 recording共同证明，模型口头声明与exit0不足以证明。
