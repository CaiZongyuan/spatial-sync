## Problem Statement

实验室平台已经能用 Newton 或 Synthetic 源跑仿真，把空间状态同步到浏览器，并通过一条动作管线让 Web、`lw` CLI 和 MCP 操作设备。但从使用者的角度，它还远不是一个能让 agent "管理实验室并训练机器人"的平台：

- **不知道实验室里有什么。** 场景写死在代码里，平台只认识一个场景名。人和 agent 都无法回答"有哪些素材、每样能做什么、缺什么、这个场景能不能启动"。用 Blender 做好的实验室（FR3 实验室，1,418 个网格）无法进入平台。
- **看不到实验室此刻的状态。** 没有培养箱、生物安全柜、环境传感器这类物联网设备，没有读数历史，也没有告警；agent 只能轮询当前值，不会被主动告知异常。
- **看不到 agent 要做什么。** agent 直接调用动作，人在执行前看不到计划和机械臂将要走的路径，事后也只能从调用列表里拼凑过程。
- **无法训练机器人。** Isaac Lab 训练在平台之外手工运行，结果无法回到平台评估、提升为设备程序；8 GB 笔记本 GPU 在训练和交互会话之间没有任何调度。
- **没有可度量的自我改进。** 既不能比较不同版本的 agent 或控制器，也没有接受规则、实验记录、成本统计和预算；agent 改了东西，没有人能说清楚它是否真的变好了、花了多少钱。
- **界面只是工程工作台。** 现有首页是下拉框加平台概况，缺少面向管理与审批的结构，视觉也不符合使用者期望的克制、精致的风格。

## Solution

把平台扩展为一个 **RSI（Recursive Self-Improvement）实验室平台**：人和 agent 通过同一套 HTTP API、`lw` CLI、MCP 与平台 skill，完成"素材 → 场景 → 计划 → 作业 → 评估 → 策略 → 部署为设备程序 → 观察失败 → 改进"的闭环，人只在关口审批。

- **库**：所有素材和场景都是带版本、带验证报告的包。平台一眼回答"有什么、能做什么、缺什么、能否启动"；FR3 实验室作为场景包导入后可启动。
- **实况与告警**：仿真里有物联网设备，真机通过 Device Host 和 MQTT 接入"实验室实况"；读数有历史、过期有标记，告警按规则触发，agent 每轮先查收件箱。
- **计划先行**：agent 先提交操作计划，界面显示步骤清单和机械臂 TCP 预览路径，执行时逐步打勾；训练也以计划提交，附带 grilling 式访谈记录和可测量的假设。
- **训练与部署**：训练是平台管理的外部作业，在计算节点上用 Isaac Lab（Newton MJWarp）运行，实时显示训练视图；检查点在平台上按评估集评估，满足接受规则后经人批准替换设备程序。
- **两层改进**：同一套版本、评估、接受规则同时改进 **Agent**（模型固定，改 Harness）和 **Controller**（本体固定，改策略、程序、奖励、数据）。评估中心、成本中心、资源页让每一次改进都可比较、可追溯、可计价。
- **新界面**：以可折叠侧栏的"仪器控制台"为框架，按页面取用图优先、编辑式与闭环看板三种布局，视觉参照 deeprsi.com 的克制质感。UI 原型 v4 是视觉与交互的参照。

## User Stories

角色：**研究员**（使用实验室的人）、**审批人**（在关口做决定的人，通常与研究员是同一人）、**agent**（通过 CLI / MCP 操作平台的 LLM agent，例如 Claude Code）、**Optimizer**（执行改进轮次的 agent 角色）、**Builder**（设计评估集的角色）、**素材工厂**（在平台外制作素材的人或 agent）、**开发者**（实现平台的工程师或 agent）。

### 库：素材与场景

1. 作为研究员，我想在素材库里看到每个素材的缩略图、ID、尺寸和六项完整度，以便快速知道实验室有哪些实物以及哪些不完整。
2. 作为研究员，我想把素材库切换成带小预览图的列表视图，以便在素材很多时快速扫描和比较。
3. 作为研究员，我想按种类（robot / device / labware / environment）筛选素材并只看有缺口的素材，以便集中处理问题。
4. 作为研究员，我想在素材详情里看到它能实现的设备类型、属性、动作和前置条件，以便知道"离心机能做什么"。
5. 作为研究员，我想在素材详情里看到来源、许可证和 provenance，以便确认素材能合法使用。
6. 作为研究员，我想看到绑定模板（哪个关节是盖子、哪些站点是孔位），以便理解素材放进场景后如何成为设备。
7. 作为研究员，我想看到某个素材被哪些场景版本引用，以便评估改动它的影响。
8. 作为素材工厂，我想用 `lw asset import <dir>` 导入一个素材包，并立即得到版本号和验证结论，以便知道是否需要返工。
9. 作为素材工厂，我想重复导入内容相同的包时得到原有版本，而不是一个新版本，以便导入可以安全重试。
10. 作为研究员，我想在场景库里看到所有场景版本（含 4 个内置场景）的卡片或列表，以及可启动状态和缺口数，以便选择要启动的实验室。
11. 作为研究员，我想看到不可启动的场景版本和具体原因（例如"示教位置 centrifuge.slot3 不可达，TCP 偏差 38 mm"），以便知道要修什么。
12. 作为研究员，我想在场景详情里看到实体树（实体与布景分开）、设备与动作、示教位置、引用的素材、验证报告和相关录制，以便全面了解一个实验室。
13. 作为研究员，我想从场景详情页一键启动会话，以便不再使用首页的下拉框。
14. 作为 agent，我想用 `lw scene show fr3-lab@2 --json` 一次拿到实体、设备能力、示教位置、缺口与验证结果，以便在操作前理解实验室。
15. 作为 agent，我想用 `lw scene launch fr3-lab` 启动最新可启动版本，以便无需记住版本号。
16. 作为 agent，我想在启动不可启动的场景时得到 `scene_not_launchable` 和失败项，以便自行判断下一步。
17. 作为研究员，我想让新录制记住它使用的场景版本，以便日后精确复现。
18. 作为研究员，我想让旧格式的录制照常回放，以便历史记录不失效。
19. 作为研究员，我想直接把未引用的用户库版本移到可恢复的回收站，并看到引用阻塞原因，以便自己或已授权的 agent 完成日常清理。
20. 作为素材工厂，我想把 FR3 实验室按顶层 Collection 拆成素材和布景、以场景包导入，并直接引用官方 FR3 素材，以便同一个机器人只有一份来源。

### 验证

21. 作为研究员，我想让导入自动运行结构检查与物理检查，以便有问题的场景不会被启动。
22. 作为研究员，我想看到每项检查的 pass / warn / fail 和对应实体，以便定位问题。
23. 作为研究员，我想在工具版本变化后看到"报告过期"的标记，以便决定是否重跑验证。
24. 作为 agent，我想用 `lw scene validate` 重跑验证并读取报告，以便修复后确认结果。
25. 作为开发者，我想让物理检查在独立子进程中用 Newton CPU 运行，以便网关不依赖 Newton。

### 实验室实况与物联网设备

26. 作为研究员，我想在"实况"页看到真实设备（培养箱、生物安全柜、环境传感器）的实时读数，以便随时掌握实验室状态。
27. 作为研究员，我想为每个数值读数看到最近 1 小时的迷你曲线，以便判断趋势。
28. 作为研究员，我想看到超时未更新的读数以灰色和"过期"标出，以便不被旧数据误导。
29. 作为研究员，我想在实况的 3D 布局图上点击设备打开抽屉，查看读数与趋势，以便空间化地浏览实验室。
30. 作为研究员，我想用"读数"开关在 3D 视图上显示或隐藏设备读数浮标，以便在信息与清晰之间切换。
31. 作为研究员，我想让真实设备与仿真孪生使用不同的 key（`/Real/…` 与 `/World/…`），以便永远不会把仿真操作发到真机。
32. 作为审批人，我想让任何对 `/Real/…` 的高风险动作都必须由我批准，以便真机安全。
33. 作为研究员，我想让实况在没有任何仿真会话时也常驻运行，以便设备 7×24 被监控。
34. 作为开发者，我想用本地 broker 和模拟设备（可注入升温、断线、风速下降）开发与测试实况，以便不依赖真实硬件。
35. 作为研究员，我想在设备断线时看到读数过期、动作返回 `device_unavailable`，以便知道设备不可用。
36. 作为研究员，我想在仿真场景中也有培养箱、生物安全柜等设备的虚拟版本，以便在没有真机时演练。

### 告警、历史与收件箱

37. 作为研究员，我想用条件语言为设备声明告警规则（条件、持续时间、严重度、提示），以便异常被自动发现。
38. 作为研究员，我想在概览、实况和侧栏徽标上看到活动告警，以便第一时间注意到。
39. 作为研究员或 agent，我想确认告警并留下备注，以便团队知道已有人处理。
40. 作为 agent，我想用 `lw inbox --since <cursor>` 拿到自上次以来需要我关注的告警、审批结果、计划变化、失败调用和作业变化，以便每轮开始时补齐上下文。
41. 作为 agent，我想在首次调用收件箱时得到所有活动告警和待审批事项，以便冷启动也不漏信息。
42. 作为 agent，我想用 `lw history <key> <property> --since 1h --every 1m` 查询降采样历史，以便分析趋势、诊断失败。
43. 作为研究员，我想让历史查询对会话录制和实况录制使用同一个接口，以便不用关心数据来自哪里。
44. 作为 agent，我想在依赖的读数过期时让前置条件以"读数已过期"失败，以便不基于旧数据行动。
45. 作为 agent，我想在 Claude Code 里用后台 `lw watch --until` 等待告警或条件，以便不轮询。

### 操作计划与路径预览

46. 作为 agent，我想在动手之前用 `lw plan create` 提交一份操作计划（动作、等待、检查，以及每步的预期结果），以便人能看到我要做什么。
47. 作为研究员，我想在会话页的视口旁看到计划步骤清单和每步状态，像 coding agent 的 plan 模式一样，以便跟踪执行进度。
48. 作为研究员，我想选中机械臂步骤时在视口里看到 TCP 虚线路径和目标处的半透明幽灵臂，以便在执行前确认动作。
49. 作为研究员，我想让策略驱动的步骤只显示目标与"由策略执行"标记，以便不被虚构的轨迹误导。
50. 作为 agent，我想用 `lw do ... --plan <id> --step <n>` 把调用关联到步骤，以便平台自动更新步骤状态。
51. 作为 agent，我想用 `lw check` 和 `lw wait ... --plan --step` 完成检查与等待步骤，以便计划中的每一步都有记录。
52. 作为 agent，我想在执行中提交计划修订，并让已完成步骤保留状态，以便适应新情况而不丢失进度。
53. 作为研究员，我想看到计划修订的差异（例如"r2 在 start 之前插入检查转子平衡"），以便理解 agent 为何改计划。
54. 作为研究员，我想看到"计划外"或"跳步"的调用被标出，以便发现偏离计划的行为。
55. 作为 agent，我想在计划提交时得到静态校验错误（实体、动作、参数、条件类型），以便提前修正。
56. 作为审批人，我想让仿真中的普通操作计划自动批准，而涉及真机或高风险动作的计划需要我批准，以便把注意力留给真正重要的事。
57. 作为研究员，我想在回放录制时看到计划面板随时间轴重现，以便事后复盘。

### 训练计划、作业与计算节点

58. 作为研究员，我想让 agent 在起草训练计划前，按 grilling 方式逐轮向我提问（失败分析、目标、算法、模型、超参、预算、评估标准），每题给出推荐答案，以便我高效地做决定。
59. 作为审批人，我想在审批卡上并排看到训练计划、完整访谈记录、相对上一轮的差异和可测量的假设，以便知道每个参数是怎么定的。
60. 作为审批人，我想批准或驳回训练计划并留备注，以便 agent 根据我的意见调整。
61. 作为 agent，我想在已批准计划声明的范围（例如 3 个 seed）内自主启动和取消作业，以便不必每个作业都请示。
62. 作为审批人，我想在作业预计超出计划剩余预算时收到审批，以便控制花费。
63. 作为研究员，我想在训练页看到所有作业的状态、所属计划、节点、进度和标题指标，以便管理多个训练过程。
64. 作为研究员，我想打开运行中的作业，看到 4 个环境的只读训练视图（10 Hz），以便直观看到机器人在学什么。
65. 作为研究员，我想在训练视图打开时仍能使用一个 CPU 交互会话，以便训练不阻塞操作。
66. 作为研究员，我想一键打开 TensorBoard 看完整曲线，以便深入分析，而平台只显示标题指标。
67. 作为研究员，我想在"资源 · 算力"看到节点、GPU 利用率、显存、租约持有者和队列，以便理解谁在占用 GPU。
68. 作为研究员，我想让训练作业持有 GPU 时新会话自动使用 CPU，以便 8 GB 显存不被争抢。
69. 作为开发者，我想让作业契约自包含（输入按引用拉取，输出上传回平台），以便以后接入远程 GPU 服务器时只需部署节点程序。
70. 作为研究员，我想让每个作业记录 Isaac Lab、Newton、Warp、torch、rsl_rl 版本、GPU 型号和 seed，以便复现。
71. 作为 agent，我想用 `lw task push` 把工作区的 Task 快照成版本，以便作业只引用确定的 Task。
72. 作为研究员，我想在节点失联超过 60 秒时看到作业失败（`node_lost`），以便不等待一个已经消失的作业。

A2 + L2 ─► T1 作业 + 节点 + 训练视图 ─► T2 评估 + 策略 + 实验记录 ─► T3 脚本程序 + 示范

- W0 与 A1 可以合并成第一个交付：新框架承载现有页面，并上线场景库。
- 每个里程碑以"能演示"为完成标准：一条本地命令启动，或在浏览器中可见。
- 每个页面随其里程碑上线；之前在导航中隐藏。
- T1 不等待 A3 与 T0：#30–#33 以 `robot-and-tubes@2`（含 FR3）开发与验收。T2 工程链使用已发布的固定 Scene/Task，`fr3-lab` 的成功接触策略保留为真实质量目标。#34 可以先评估 `lab-demo` 的 virtual 程序。
- SF 与 #18 独立，沿用已交付的 A1/A2 基础；本期终点是可运行新场景、复用补制物件和验证失败后的修复，不承担完整机器人操作或训练验收。

### 模块

以下模块按"深模块"设计：接口小、实现可以复杂。每个模块的对外接口就是测试的接缝。

1. **库（library）**：扫描内置库与用户库两个根，解析 `<kind>/<name>@<rev>` 与 `<name>@<rev>`，计算内容哈希，导入 tar 包并分配版本，展开绑定模板，运行结构检查 S1–S8。对外接口：列表与筛选、按 ID 解析（省略 rev 时取最新或最新可启动）、导入、验证、普通撤下与恢复（兼容旧删除审批）、引用查询。与 Newton 无关。
2. **物理验证器**：在独立子进程中用 Newton CPU 运行 P1–P6，输出验证报告。对外接口：`validate(subject) → ValidationReport`。网关只读报告，不 import Newton。
3. **场景加载**：把场景版本交给 Runner。Python builder 场景走现有 builder；USD 场景解析 `@library:` 引用，只把实体导入 Newton，布景以 `StaticNode` + GLB 写入 Manifest。删除硬编码的场景列表。
4. **信息平面扩展**（保持设备无关）：
   - 新设备类型与 virtual 程序：`incubator/v1`、`biosafety-cabinet/v1`、`env-sensor/v1`；
   - 属性 `staleAfterSeconds` 与过期语义；
   - 条件语言新增 `deviatesFrom`、`stale`，Python 与 TS 两套求值器共用夹具表；
   - **告警引擎**放在网关状态存储一侧：从 YAML 规则编译，按观测更新与定时器判定 `forSeconds`，发出 `entity.alert`。设备代码不写告警逻辑。
5. **实验室实况宿主（Device Host）**：在网关进程内常驻，按墙钟推进，使用与 Runner 相同的 Program 接口；`*.mqtt` 程序把 topic 映射为属性和动作；断线时属性按 `staleAfterSeconds` 过期，动作返回 `device_unavailable`。实况录制按天分段。
6. **历史服务**：从会话录制或实况录制读取 `(entityKey, property)` 序列，利用段属性索引，按 `mean / last / min / max` 降采样，单次最多 2,000 点。
7. **收件箱**：在网关序号与实况录制之上的游标视图，按种类过滤需要 agent 关注的消息；游标跨网关重启有效。
8. **Plan 存储**：一个通用 Plan 对象，`kind` 为 `operation` 或 `training`；修订、步骤状态、静态校验、审批判定。调用请求新增可选的 `planId`、`stepId`，平台据此把调用状态映射为步骤状态。平台不执行计划。
9. **路径预览**：Program 接口新增可选 `preview(action, params)`；示教程序用现有轨迹规划加正运动学生成 TCP 折线与目标关节角，策略程序只返回目标；结果按（计划修订、步骤、当前关节状态）缓存。
10. **审批**：复用信息规格的审批机制，审批对象扩展为 `invocation / plan / policy / job / deletion`；`lw approve` 要求 TTY 人工确认；MCP 不提供审批工具；记录操作者、时间、备注。
11. **训练编排（training）**：Task 版本、训练计划预算估算、作业状态机、作业契约、GPU 租约与队列。与 Isaac Lab 无关，可用假节点测试。
12. **计算节点程序（node）**：拉取输入、在 Isaac Lab 环境中启动训练、通过 `--external_callback` 注入训练视图与心跳桥接、上传产物。v1 只有本机节点，由网关以子进程启动；节点与网关之间用本机令牌认证。
13. **训练视图**：网关为每个运行中的作业提供只读视图，复用空间协议；Manifest 来自作业的场景版本，Transform 来自节点转发；多个环境以 `envIndex` 区分。不是会话，不录制，可同时多个。
14. **评估器**：在平台会话中顺序运行评估集的回合，每个回合录制，按 Task 的 `success` 条件判定，计算分阶段通过率与 Wilson 区间，写入记分板；评估期间占用单活跃会话，交互操作排队。
15. **策略程序**：`robot_arm.policy` 用 onnxruntime 在 CPU 上按 Task 控制频率推理，实现 `robot-arm/v1`；使用接触抓取；动作参数超出训练覆盖范围时以 `precondition_failed` 拒绝。观测一致性测试是独立工具。
16. **RSI 记录**：Agent 与 Harness 版本、快照；Embodiment、Controller 版本、Robot Model 目录；评估集与记分板；实验记录（按目标，Markdown + YAML 头）；闭环预算；接受规则判定。
17. **Agent 运行器**：作业类型 `agent-run`，v1 实现 Claude Agent SDK 适配器；在专属工作目录加载 Harness，连接平台 MCP / CLI，执行题面；评估中遇到人工关口一律自动驳回并计入评分；输出 Trace、最终状态快照、用量记录。
18. **成本账本**：记录 LLM 用量（Agent、Harness 版本、模型、输入 / 输出 / 缓存 Token、成功或失败、所属 Plan 与评估）与 GPU 秒（节点、作业、所属 Plan）；价格表由人配置；按时间、Agent、模型、节点、目标、Plan 聚合；异常列表与已读状态。
19. **Vault**：本机文件，权限 0600，只以环境变量注入适配器进程；`ls` 只返回名称。
20. **CLI / MCP**：新增命令组 `asset / scene / plan / check / history / alerts / inbox / task / job / node / eval / policy / program / demo / notebook / loop / agent / harness / suite / score / cost / model / vault / robot / robot-model / controller / skills`。MCP 工具由同一张命令表生成，保持通用，不提供审批与 Vault 工具。
21. **平台 skill**：放在仓库的平台 skill 目录，与开发 skill 分开；首批 `lab`、`lab-operate`、`lab-library`、`lab-training-plan`、`lab-train-evaluate`、`lab-eval-build`、`lab-harness-optimize`；`lw skills install` 安装；CI 校验命令存在性。
22. **Web**：见 Lab Web UI 规格。要点：沿用现有 React + TanStack Router + react-three-fiber；设计令牌来自原型 v4；视口增加正交等距相机与 HTML 叠加层；图表用自研 SVG 组件；字体本地打包，不访问网络。

| entityKey 命名空间 | `/Real/…` 保留给实况 | 仿真实体继续使用 `/World/…` |
| 审批 | 新增审批对象类型 | 现有调用审批不变 |
| 会话创建 | 接受 `sceneVersion`；`sceneId` 继续接受并解析为最新可启动版本 | 旧客户端不受影响 |

开发涉及以上契约时，使用 `change-impact` 找出真实消费者并证明兼容性。

### 错误码（新增）

| 码 | 状态 | 场景 |
|---|---|---|
| `scene_not_launchable` | 409 | 启动验证未通过的场景版本，附失败项 |
| `unknown_version` | 404 | 库中不存在该 ID 或 rev |
| `version_in_use` | 409 | 删除仍被引用的版本，附引用方 |
| `import_invalid` | 422 | 导入包结构或 schema 不合法，附问题列表 |
| `invalid_plan` | 422 | 计划静态校验失败，指出步骤 |
| `plan_not_approved` | 409 | 在计划未批准时启动作业或执行需审批的步骤 |
| `pending_approval` | 202 | 请求需要人工审批，返回审批 ID |
| `approval_requires_human` | 403 | 非交互方式或 MCP 尝试审批 |
| `device_unavailable` | 409 | 实况设备断线或命令确认超时 |

## Testing Decisions

### 什么是好测试

- 只测外部行为：HTTP 响应、CLI 输出与退出码、协议消息、录制内容、浏览器中可见的结果。不测私有函数、不断言内部数据结构。
- 用最高的接缝：一个用户故事优先在网关 HTTP 层或 `lw` 层验证，而不是拆成多个内部单元测试。
- 纯函数只在逻辑密集、组合多的地方单测：条件求值、告警状态机、降采样、Wilson 区间与接受规则、预算估算、步骤状态映射、TCP 预览几何、内容哈希、绑定模板展开、成本聚合。
- 真物理、真 Isaac Lab、真 Agent SDK、真 MQTT 硬件只在手动 smoke 中验证；CI 保持无 GPU、5 分钟以内。

### 接缝

| 接缝 | 用于 | 先例 |
|---|---|---|
| **网关 HTTP / WS（进程内，Synthetic 源）** | 主接缝：库导入与解析、按版本启动、告警、历史、收件箱、计划与步骤映射、审批、作业状态机、评估记分板、成本聚合 | 现有网关测试（基于 Synthetic 宿主的拒绝码、busy、cancel、reset、等待、长轮询） |
| **`lw` 真实入口 + 官方 MCP SDK 客户端** | 每个新命令的输出与退出码；MCP 镜像工具逐个调用；`lw approve` 非 TTY 拒绝；skill 命令存在性检查 | 现有 CLI / MCP / stdio 测试 |
| **契约测试与夹具** | 协议 2.1 的 Pydantic 与 TS 类型一致；录制 v1 / v2 互读；验证报告、记分板、作业契约、心跳的 schema；条件求值共用夹具表 | 现有协议契约测试、条件夹具、录制夹具 |
| **浏览器 E2E（Playwright，对 Synthetic API）** | 每个页面的关键旅程：场景库启动会话、告警确认、计划清单打勾与路径预览出现、审批卡批准与撤销、评估集计分板、成本筛选、资源标签页 | 现有信息、回放、平台、工作台 E2E |
| **纯函数单测** | 上文列出的逻辑密集处 | 现有单元测试（条件、差分、调用状态机、轨迹规划） |
| **手动 smoke** | P1–P6 物理检查、FR3 接触抓取训练、真实作业节点、观测一致性、Agent SDK 运行、本地 broker 与模拟设备 | 现有 Newton smoke 工具与基准 |

### 新增测试替身

- **假节点**：在测试中代替计算节点程序，按脚本推进作业状态、发心跳、上传假产物，用于作业、租约、超预算、失联的网关测试。
- **进程内假 broker**：代替 MQTT broker，用于实况遥测映射、命令确认与超时、断线过期。
- **假 Agent 适配器**：按脚本调用平台并产出 Trace 与用量，用于 Agent 运行、记分板、成本账本、接受规则的测试。
- **小型样例库**：一个合法素材、一个缺许可证和碰撞体的素材、一个示教位置被改坏的场景包，用于导入与验证测试。
- **录制夹具 v2**：新增一份 Synthetic 场景 10 s 录制（< 1 MB），v1 夹具保留。

## Out of Scope

- 平台内的场景搭建与建模（Web 编辑、agent 在平台内放置物体）。场景由平台外的素材工厂制作后导入；SF 包含本仓库独立维护的外部 Blender／OpenUSD 工厂脚本，网关不依赖 Blender，不建设通用导出插件框架。
- 视觉检查（自动渲染评审）与 Isaac Sim 资产校验器。
- 场景变体、初始条件预设与域随机化的平台化管理（Task 内部可以自行随机化）。
- Synthetic 源运行 USD 场景。
- MQTT 以外的设备协议与具体硬件驱动。
- 实验流程编排引擎；预测性预演（克隆仿真分支试跑）。
- 数据库与时序数据库；多用户、账户、权限、计费结算；任何部署工作。
- PhysX 后端；视觉策略与蒸馏；自动超参搜索；多 GPU 分布式训练；真机部署与 sim-to-real。
- VLA 推理与微调（只登记）；Default 之外的 RSI 算法（只定义接入协议）。
- 远程计算节点的实现（只定义契约）；远程库存储。
- 自建实验指标存储（SwanLab、W&B 等可由 Task 自行接入）。
- 移动端专门适配（桌面 Web 为验收范围，窄屏只要求不破版）。
