# Hugging Face 资产元数据维护平台

> Specification v1.0 · 2026-10-26 · 用户已确认方向，待实施。
>
> 跟踪：[Spec #196](https://github.com/CaiZongyuan/spatial-sync/issues/196)。实施票、状态与交付证据在该 issue 维护。
>
> 本规格定义本机、轻量、以 Hugging Face Dataset 为中心的资产元数据维护能力。后台 Agent 按维护 skills 自动构建与更新完整数据集的元数据，供用户和使用素材的 Agent 共用检索。GitHub、项目站和 Space 是数据集的关联说明、目录或浏览入口。

## Problem Statement

用户面对的是一页不断追加、信息过载的在线素材卡片。多数候选只有从包名整理的名称，大量属性未知，缺乏有用分类、tags 和摘要；预览还会把材质／法线贴图当作物体图。用户和 Agent 即使知道物体的用途，也难以找到并比较合适内容。

目前的全量同步主要建立身份清单，打开详情补充的来源信息不会改善检索。缺少一个可持续维护的本机元数据库，也没有让后台 Agent 统一采集、整理、修正和发布元数据的流程。未来接入更多 Hugging Face 数据集后，这些问题会被不同的目录结构、字段和版本放大。

这些数据集大多托管在同一平台，GitHub 和项目站通常是说明或辅助目录；把它们都设计为对等的独立资产源，会增加重复收录、重复抓取和维护成本。用户希望有平台能力，同时保持解耦、轻量和清晰的设计。

## Solution

建立以 Source Collection 为维护单位的本机 External Asset Catalog：Hugging Face Dataset 是主要身份与版本入口，一套共享 Hub 连接能力处理版本、分页和读取，各数据集只保留必要的结构解析配方。关联说明、目录与预览作为该数据集的依据和资源进入维护流程。

先为选定集合建立完整清单，再由后台 Agent 使用一套版本化维护 skills，分批导入现成字段、整理双语名称、类别、tags、摘要和其他有依据的元信息。结果持久保存、可中断续跑、可增量更新，经过自动校验后发布为一致的 Catalog Release。

用户和 Agent 通过同一套检索、筛选与有界详情接口使用发布结果。人的界面提供明确分页、紧凑卡片、正确物体预览和分层详情；维护进度按真实覆盖统计呈现。Lab World 组合自己的本地素材、获取与验证结果，元数据维护核心保持独立于仿真、建模和设备行为。

## User Stories

1. 作为本机维护者，我希望用 Hugging Face Dataset 身份登记来源集合，以便维护单位稳定而不依赖某个浏览页面。
2. 作为本机维护者，我希望将 GitHub、项目站、Space 和 Viewer 关联到所属数据集，以便保留说明入口并避免重复建库。
3. 作为目录维护 Agent，我希望读取来源档案和官方结构说明，以便选择现成的枚举与解析方式。
4. 作为目录维护 Agent，我希望固定数据集版本和关联资料的版本，以便重新运行时得到可解释的输入。
5. 作为本机维护者，我希望同一套维护流程支持 SimReady、Scenario 和 ChemLab，以便新增同平台数据集无需再造整套系统。
6. 作为本机维护者，我希望从 Hugging Face 的 3D 数据集入口发现候选集合，以便持续扩充目录。
7. 作为本机维护者，我希望选择哪些候选集合启用自动维护，以便控制网络与模型资源。
8. 作为目录维护 Agent，我希望区分公开身份、受限访问和无法读取的资源，以便报告缺口而不是把空结果视为完整覆盖。
9. 作为用户，我希望看到数据集的完整条目清单，以便发现范围不再局限于少量精选项。
10. 作为用户，我希望看到清单覆盖与整理覆盖分别统计，以便知道哪些内容已经被发现、哪些仍需补齐。
11. 作为本机维护者，我希望明确区分条目、表格行、模型变体和文件数量，以便规模统计不误导使用者。
12. 作为目录维护 Agent，我希望直接导入上游已有结构化名称、尺寸、类别和文件索引，以便减少模型重写与重复推断。
13. 作为用户，我希望有中英文名称、别名和简短摘要，以便快速理解原始 ID 难以表达的物体。
14. 作为用户，我希望按跨数据集的物体类别浏览，以便不必先了解每个发布者的命名方式。
15. 作为用户，我希望按 tags、应用领域、场景用途和结构属性检索，以便表达比素材大类更具体的需求。
16. 作为使用素材的 Agent，我希望获得规范化但保留原文的描述，以便兼顾一致检索和来源核对。
17. 作为用户，我希望了解格式、变体、已知尺寸、单位、来源字节及部件信息，以便比较素材的使用与适配成本。
18. 作为用户，我希望未知属性明确保持未知，以便不因缺失值被当作零或满足条件而误选素材。
19. 作为用户，我希望查看字段依据和整理来源，以便判断它来自发布者、确定性提取还是 Agent 的组织描述。
20. 作为使用素材的 Agent，我希望区分许可声明、访问条件和消费方准入，以便正确解释可发现与可获取的差异。
21. 作为用户，我希望看到真正的物体预览，以便在打开详情前辨认内容。
22. 作为用户，我希望缺图、读取失败与未采集有不同状态，以便知道是否值得重试。
23. 作为本机维护者，我希望预览使用稳定资源定位并缓存已读取内容，以便临时签名 URL 过期后仍能恢复显示。
24. 作为本机维护者，我希望后台 Agent 按统一 skills 自动维护集合，以便不必逐项手工填写元数据。
25. 作为目录维护 Agent，我希望按批次读取待整理条目并提交结构化结果，以便处理整个集合而不依赖一次超长上下文。
26. 作为目录维护 Agent，我希望读取必要的原始依据，以便摘要和标签能对照来源。
27. 作为本机维护者，我希望服务运行时可按计划检查来源变化，以便目录持续更新。
28. 作为本机维护者，我希望手动启动、取消、重试并继续维护，以便控制一次任务的范围与时机。
29. 作为本机维护者，我希望服务或 worker 重启后从检查点恢复，以便已完成整理不会丢失。
30. 作为本机维护者，我希望未变化条目复用现有结果，以便减少网络、模型用量和重复工作。
31. 作为本机维护者，我希望看到阶段、实际处理数、失败与资源用量，以便了解后台是否有效推进。
32. 作为本机维护者，我希望每次维护受网络、模型用量和运行时长限额约束，以便自动运行保持可控。
33. 作为本机维护者，我希望单项失败被隔离并可定向修复，以便少数异常不拖垮其他条目的维护。
34. 作为用户，我希望人工更正的名称、类别和 tags 在重跑后保留，以便错误不会反复出现。
35. 作为本机维护者，我希望冲突可追溯、整理版本可撤回，以便修复错误批次而不修改历史来源事实。
36. 作为用户，我希望后台维护期间仍能搜索已发布目录，以便浏览不等待抓取或模型调用。
37. 作为用户，我希望关键词、双语别名、类别和 tags 都参与检索，以便不同表达能找到相关素材。
38. 作为使用素材的 Agent，我希望自然语言检索可以补充关键词召回，以便用途描述不必精确匹配包名。
39. 作为使用素材的 Agent，我希望硬条件独立执行并解释零结果，以便相似性不会放宽尺寸或其他明确约束。
40. 作为用户，我希望切换本地、在线和全部范围时保留一致语义，以便将外部候选与已有本地版本一起比较。
41. 作为用户，我希望页面有上一页、下一页和页定位，以便浏览可预测而不是不断增长。
42. 作为用户，我希望查询、条件和页位置能通过 URL 恢复，以便返回或分享时保持上下文。
43. 作为用户，我希望卡片优先显示名称、摘要、预览和关键标签，以便快速扫描而不被技术细节淹没。
44. 作为用户，我希望详情按概览、技术信息和来源证据展开，以便在需要时再读取复杂信息。
45. 作为用户，我希望获取预算在准备获取时展示，以便估算信息不干扰发现流程。
46. 作为使用素材的 Agent，我希望通过有界分页和精确版本读取比较候选，以便不必先拉取全量目录。
47. 作为使用素材的 Agent，我希望 CLI、MCP 和 Web 共享同一 HTTP 行为，以便入口改变不影响身份、过滤和发布结果。
48. 作为本机维护者，我希望发布的数据与检索索引保持一致，以便不会查询到一半更新的目录。
49. 作为用户，我希望翻页期间目录保持同一发布版本，以便更新不会造成重复、遗漏或版本混杂。
50. 作为本机维护者，我希望来源失败或索引构建失败时保留旧发布，以便目录持续可用。
51. 作为用户，我希望断网时读取最近目录和已缓存内容，以便本机工作台仍可使用。
52. 作为本机维护者，我希望导出与恢复元数据和更正，以便本机数据有可迁移、可备份的形态。
53. 作为 Lab World 使用者，我希望历史本地素材、场景和录制仍引用原精确版本，以便维护目录不会破坏既有工作。
54. 作为开发者，我希望维护核心不依赖 Newton、Blender 或设备模型，以便它可以独立验证并由不同使用方接入。
55. 作为开发者，我希望以少量共用模块和现有公开接口验证整条流程，以便扩展来源不会引入大量服务和测试接缝。
56. 作为本机维护者，我希望看到跨来源的真实检索质量和维护覆盖证据，以便判断目录是否比原有包名检索更有用。

## Implementation Decisions

- **部署与依赖**：首期采用模块化本机应用，复用现有 API 宿主；元数据核心在代码依赖上独立，后台维护在独立 worker 进程执行。需要时才能增加单独部署方式，本期不强制拆成多个 HTTP 服务。
- **轻量资源**：SQLite 保存目录、版本、依据引用、更正、维护批次与发布状态，普通文件保存原始元数据与预览。使用事务和本机有界队列；不新增网络数据库、消息代理、图数据库或独立向量服务。
- **最小模块边界**：保留来源读取与数据集配方、持久目录与发布、后台维护、查询与消费适配四个职责。先复用现有传输、持久化和检索能力，仅对三种实际数据结构的差异建立解析配方，不引入通用插件平台、爬虫 DSL 或供应商框架。
- **Hugging Face 优先**：Source Collection 以 Hugging Face Dataset 的稳定仓库身份为主。共用版本解析、文件树分页、受控读取和表格元数据处理；GitHub、项目站、Space 和 Viewer 默认作为关联说明、目录或浏览资源，不因增加一个 URL 就增加一个独立资产来源。
- **首批集合**：接入 NVIDIA SimReady 原始数据集、Scenario 3D Collection、ChemLab Assets。HF 3D 列表用于候选发现；只对启用集合自动深度维护，不隐式处理全站所有数据集。
- **来源档案**：记录发布者、主数据集、关联入口角色、内容类型、访问状态、枚举单位、元数据位置和解析配方。关联资料各自固定版本或内容摘要，不能把 GitHub commit 当作 HF commit。
- **版本化枚举**：先固定主数据集版本，再遍历完整分页、分片与所需子清单。Dataset Viewer 仅在覆盖与返回 revision 符合目标时使用；否则读取固定版本原始元数据。不将 partial 响应或一个 split 的行数称为全库覆盖。
- **条目身份**：Catalog Entry 保留集合内上游稳定 ID，精确内容身份绑定来源版本及已知内容摘要；显示名称、翻译、tags 与托管 URL 不作身份。一个条目可包含多个模型表示或输出变体；图片与辅助资料单独分类。
- **跨源关系**：来源别名、相同内容和语义相似分别表达。同名或语义接近不合并身份与许可；清晰的关联证据可去除重复登记，但保留原始出处。
- **元数据范围**：统一保存中英名称、别名、短摘要、类别、tags、领域／场景用途，以及有依据的格式、文件量、单位、坐标约定、尺寸、几何／材质、部件／关节、许可、预览和来源引用。保留必要的来源扩展字段，不为每个项目发明一套公共 schema。
- **事实与整理**：已有结构化字段优先确定性导入；Agent 主要做来源理解、归一化、分类摘要和异常修复。发布者声明、提取／测量、Agent 整理和实际验证保留不同归属。未知不当零，不由模型补成已验证尺寸、碰撞或许可事实。
- **分类与 tags**：Catalog Category 是跨集合的版本化物体分类；tags 支持规范标签、原始标签和双语别名。领域、用途和结构属性均可表达，并与本地 Asset kind 和 EntityType 分开。类别映射与词表变化可追溯，检索与筛选使用同一词表版本。
- **更正合成**：人工更正作为独立覆盖层，重跑不得静默覆盖。来源事实和 Agent 整理按字段职责组合；冲突记录依据与原因，支持查看、修复和撤回整理选择。更正不改变历史物理验证。
- **维护 skills**：交付一个版本化维护入口，按需加载来源建档、字段提取、分类摘要、预览检查、审计修复等工作流程和来源配方。它们是同一套维护能力，不要求为每个阶段创建一个长期运行的 Agent。
- **运行时边界**：轻量 supervisor 调用已配置的 Agent Runtime 执行后台维护，运行时拥有模型、凭据、工具上下文和原生会话。复用实际回执记录用量；当前运行时记录导入不冒充已有自动执行能力。未配置运行时时保留确定性提取结果并报告待配置，不选择隐藏的付费默认值。
- **任务控制**：按集合版本启动维护并持久记录清单与批次，支持手动、运行中的定时检查和来源变化触发。每集合一个编排运行，批次有界并行；恢复、重试与重复提交以稳定任务／输入键去重，不依赖 Agent 对话记忆或分布式调度系统。
- **维护阶段**：运行涵盖枚举、提取、整理、检查、发布，以及成功、部分完成、失败、取消、中断等明确终态。每个条目或批次都有结构化结果；Agent 的文字完成声明不能替代实际发布和覆盖。
- **写入契约**：通过共享 HTTP 提供来源／任务查询、待办批次领取、依据读取、批量提交、错误报告、更正和发布能力，CLI／MCP 调用同一行为。提交绑定运行、输入摘要、基础版本和配方／skills／词表版本；并发更正须检测冲突，worker 不直接修改数据库或索引文件。
- **增量与预算**：输入未变的条目复用结果；变化、失败与受影响项定向重处理。每次运行记录实际请求、网络字节、预览字节、模型用量和时长，应用可配置上限并尊重来源限流。达到限额保存检查点；未知用量不记零。新来源版本不自动继承旧许可或物理准入。
- **后台与浏览分离**：轻量目录同步和前台搜索保持可用；后台整理可以按预算批量读取必要元数据。翻页、搜索和普通列表读取不触发后台建库或全量上游下载。预览路径／角色可以全量整理，图片正文默认按需读取；必要的后台质量抽查受独立字节预算约束。
- **资源读取**：先使用集合原生索引、manifest、JSON 和 Parquet，避免逐页浏览重建已有资料。单条说明、表格元数据、预览和主模型分别限额；允许有界表格读取覆盖已调查的约 17 MB Parquet，不因该需要放开主模型或解包限制。内嵌预览计入实际传输。
- **预览选择**：先确定物体预览角色并排除材质、法线等贴图，再选择尺寸适当的候选。保存稳定路径与内容摘要，不把临时签名 URL 当作长期身份。区分未采集、可用、缺失、失败和疑似错误图；预览缺口不阻塞完整身份清单发布。
- **发布一致性**：Catalog Release 绑定来源版本集合、元数据／更正选择、词表与索引版本。校验和索引就绪后原子发布；失败继续读旧发布。清单完整但整理未完成可发布明确标注覆盖的目录；枚举未闭合不得替换为该集合的完整新版本。
- **检索契约**：复用精确 ID、关键词、双语和 CPU 多语言语义能力，加入类别、tags 和丰富描述。词法与语义可以组合召回，再保持硬条件独立执行；精确版本不能被相似候选替换。结果说明条件、匹配依据、未知项、发布版本和继续读取方式，零结果不隐式放宽。
- **分页与响应**：保留既有有界响应、游标和默认大小兼容行为；Web 默认每页 24 项并支持上一页、下一页及页定位。查询、条件、排序、页大小与发布标识进入 URL；同一分页链固定发布视图并以稳定身份处理同分排序。过期发布给出明确重查方式。
- **人的信息层级**：卡片优先展示物体预览、可读名称、一句摘要、来源、类别／少量 tags 和紧凑可用状态，可切列表。详情先概览与技术信息，再按需展开完整身份、未知项和来源证据；获取预算在准备获取时展示。
- **离线与历史**：最近发布、元数据与已缓存依据／图片断网可读，支持目录导出恢复。图片缓存可以有界淘汰；元数据历史、人工更正及现有精确引用分开保留。旧目录格式和已发布引用有版本化迁移／兼容读取，不删除本地素材、场景或录制依赖。
- **Lab World 集成**：本地 Asset 版本、获取准入、物理验证、设备行为和场景引用属于消费适配层。元数据核心不导入实验室运行时或拥有设备模型；保留现有 HTTP／CLI／MCP 搜索、描述和估算行为。空间协议、录制格式、entityKey、几何转换和统一动作管线保持既有契约。

## Testing Decisions

- **主要接缝**：复用现有公开 HTTP 旅程，覆盖登记／维护集合、批次结果提交、发布、检索／详情、重启与旧精确版本读取。来源连接使用一个可控上游 HTTP 夹具，worker 在外部运行时进程边界提供确定性结果；优先通过公开效果验证，不增加多层业务测试接口。
- **好测试的标准**：断言可观察的身份、字段、依据、覆盖、发布、错误和恢复结果；不绑定内部函数调用次数、数据库表布局或 Agent 文案。必要的上游请求统计用于证明搜索零上游请求、未变输入复用与无主模型下载等真实行为。
- **既有先例**：复用目录完整分页／取消重试／失败保留旧发布／离线重启旅程、懒加载与缓存复用测试、真实 CLI 和官方 MCP 传输一致性测试，以及目录搜索和更新的浏览器旅程。CLI／MCP 主要验证传输同值，不复制一套业务断言。
- **三类结构**：固定小型 SimReady 包清单、Scenario 表格和 ChemLab 联合索引，验证同一维护 API 支持三种解析配方。ChemLab 的仪器与器具／家具必须联合对账；Scenario 的例子数与输出文件数分别报告。
- **全量与部分覆盖**：验证跨分页、分片、子集合、partial Viewer、revision 不匹配、缺失字段和未知分母；只有完整身份清单可替换完整发布。实际来源覆盖必须对账清单身份，不能用夹具或少量抽样冒充全库。
- **自动维护**：通过真实任务控制与确定性运行时替身验证分批写入、重复提交、输入未变复用、变化项处理、取消、超时、限流、预算耗尽、worker 崩溃、服务重启及单项／单源失败恢复。来源和整理产物不得产生虚假模型用量或完成记录。
- **更正与依据**：验证人工覆盖保留、并发冲突、整理撤回、依据可回看、未知技术字段不被生成描述提升，以及来源版本／整理版本／本地 Asset 版本分别保持。
- **预览**：使用同时含真正物体图和更小 normal 图的夹具覆盖真实误选；另覆盖缺图、读取失败、显式重试、签名链接过期、缓存淘汰和离线读取。前台列表不直接请求外部图片，后台抽查和按需读取遵守各自预算。
- **发布与分页**：验证索引构建失败保留旧发布、原子发布、当前分页不混入新版本、稳定排序、URL 恢复、上一页／下一页／页定位，以及过期游标明确重查。索引可从持久元数据重建。
- **业务兼容**：读取旧格式目录与精确来源引用，验证既有本地／在线／全部范围、描述、估算、已安装关联和历史版本。目录更新不能删除或改变既有 Asset、场景与录制。
- **人的旅程**：浏览器从分类／tags／中英文查询开始，翻页、打开详情、查看依据和维护状态、进入获取估算；验证卡片信息层级与真实预览状态，失败和零结果均能解释。
- **检索质量**：固定至少 100 项代表记录、40 条中英文查询，每种语言至少 8 条保留查询不参与调优，覆盖三来源、精确定位、类别／tags／用途、硬条件、未知及零结果。独立初标、用户抽查争议；有相关候选的保留查询以前五项命中至少 90% 为目标，逐语言报告分母与结果，精确身份和硬条件用例必须全部正确。
- **性能与轻量验证**：沿用现有 GPU-free Linux／WSL 基线，在千条记录、模型已加载时检索 P95 不超过 2 秒，冷启动另报。报告数据版本、CPU、运行用量与缓存口径；验证元数据核心在没有 Newton、Blender、GPU 和外部数据库服务时可运行。
- **交付门禁**：实现阶段执行仓库 Mandatory checks；CI 使用固定夹具和确定性 Agent 替身，无在线全量、GPU 或付费模型依赖。真实来源构建及真实 Agent 旅程另留版本、完整覆盖、检索效果和实际资源证据；配置具体运行时及用量预算后再进行真实模型执行，不能把接口通过当作整理质量通过。

## Out of Scope

- 云端集中托管、多用户权限、公共素材托管与再分发服务，以及独立的跨站通用爬虫平台。
- 将 GitHub 或任意项目站当作与 HF Dataset 对等的独立资产源，或自动维护整个 Hugging Face 站点。
- 分布式任务集群、消息代理、图数据库、独立向量数据库服务、通用插件／映射语言，以及首期强制微服务拆分。
- 为建库预下载全部 3D 主文件、所有图片或全部深层内容；为每项缺图自动下载并离线渲染模型。
- 任意格式自动适配、全库获取准入、许可或物理质量的无依据保证、自动创建设备行为、新机器人动力学和训练交付。
- Web 场景编辑器、内置制作聊天和已取消的 Agent 场景制作过程页面。
- 修改空间协议、录制格式、entityKey、几何约定或设备动作管线；目录整理不回写已导入素材内容。
- 未经具体运行时与用量预算确认的付费模型执行、GPU 任务和资产对外发布。
