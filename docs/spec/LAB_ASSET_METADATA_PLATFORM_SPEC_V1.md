# 仓库内轻量素材目录

> v1.1 · 2026-10-28。按用户最新要求修订，取代此前默认建设完整元数据维护平台的范围。既有显式 MetadataStore/独立宿主的兼容行为由操作指引的旧式部署部分说明。

## 目标

用户和 Agent 共用一份本地检索资料，快速知道三个来源中有什么素材、用途与下载位置。来源为 NVIDIA SimReady、Scenario 3D Collection、ChemLab Assets。Agent 采集来源并整理名称、摘要、标签和物体缩略图，平台保存并查询结果。

## 保存与身份

- `catalog/data/sources.json` 保存每个集合的 dataset、固定 revision 和来源链接。
- 三份稳定排序的 JSONL 与去重 WebP（`catalog/thumbnails/`）随 Git 保存。
- `catalog/local/catalog.sqlite3` 是生成的查询缓存，临时文件和简要同步状态也保存在被 Git 忽略的 `catalog/local/`。
- 每项记录保留上游稳定 ID、双语名称与摘要、别名、类别、tags、下载变体路径/格式、许可声明与来源、已知尺寸和字节数、物体图片定位。未知属性保持未知。
- 对外精确身份由集合、正确编码的上游 ID 和固定 revision 组成。不可用的固定版本明确拒绝；不将当前版本当作旧版本返回。
- 目录更新不修改已经导入的 Asset、Scene 或 recording；它们的版本和引用继续由原系统管理。

## 更新

`tools/sync_catalog.py --sync-source <id> [--revision <sha>]` 通过既有 HF 读取配方读取固定版本。省略 revision 时使用来源清单中的固定版本，不把现有记录直接改标签冒充来源更新。

只有完整、无条目提取错误的读取结果进入合并和发布。来源不可达、条目元数据失败或候选校验失败时，该来源原有可用资料保持原样，失败身份与原因写入简要状态。其他来源可以单独更新。

未变输入复用已有整理和缩略图；内容变化后保留稳定身份名称及别名，依据新的来源事实更新用途说明与分类，记录实际缺口。重复同步保持稳定字节，不积累完整历史副本。

候选 JSONL、来源清单和完整 SQLite 先在本地临时目录准备、验证。提交与冷启动缓存校验共用本地文件锁；运行中的查询只跟随已提交 SQLite 的代际。更新过程、失败回滚和并发读取均不能暴露新条目配旧 revision 的组合。

来源网络读取可以重叠，合并时重新读取最新已提交资料，序列化写入，避免一个来源覆盖另一个来源的更新。

## 查询

Web、CLI 和 MCP 共用现有 HTTP 检索入口，普通素材检索和原生元数据读取使用同一已提交版本。统一索引在版本变化时刷新，单次读取固定不可变快照。旧分页引用过期时明确要求重查。

搜索、筛选、分页和已有字段详情只读取本地数据。图片读取单独处理，联网补图失败不阻塞搜索。初次启动会校验/建立缓存；手工编辑 JSONL 或拉取新资料后，可显式 `--rebuild` 或重启宿主。

默认模式不显示旧的维护批次、Runtime、集合开关和目录同步按钮，旧写接口返回明确的不支持结果。实际获取模型仍由原有获取流程负责，资料可发现不等于平台已经批准获取或验证物理能力。

## 图片与 Agent 整理

来源物体图按现有确定性转换生成 WebP：最长边 384，不放大，quality 78、method 4，保留透明度。按内容去重并校验文件；来源确实缺图时显示准确占位，材质或法线图不代替物体图。

Agent 在自己的会话中整理有依据的摘要、别名和类别，复用有用内容与人工更正。同步脚本不托管模型或重建预算/批次平台。同步不下载全部模型，也不为缺图自动渲染模型。

## 验收

1. 三源身份与固定版本对账；名称、别名、类别、tags 和关键词检索可用，下载定位可复核。
2. 在真实 HTTP 旅程中，来源新增、变化与删除能同时出现在普通检索和原生读取；精确旧版本与旧游标正确拒绝。
3. 来源失败、单条提取失败、缓存安装失败保留旧资料；发布中旧/新进程读者只看到完整提交版本。
4. 重启或删除隔离查询缓存后，可以仅从版本化资料重建；重复同步不增加历史副本或无意义 Git diff。
5. 断网可搜索、读取已有字段和本地图；报告缺图、来源缺失和读取失败的实际数量。
6. 报告文本、WebP、SQLite 和 Git 的实际字节，以及注明机器、数据量和冷/热状态的查询时间。估算与实测分开。
7. 运行 `docs/VERIFICATION.md` 的 Mandatory checks，使用隔离根和 GPU-free 夹具；额外核实默认工作台的真实浏览器查询。

当前数据回执、复现和交付状态进入 issue/PR；原始记录放 `.scratch/`。本规格描述运行范围，完整维护平台、长期原文证据档案、逐字段回执和多份历史发布不作为默认检索层要求。
