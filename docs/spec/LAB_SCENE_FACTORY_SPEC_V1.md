## 1. 交付目标

用户在 Claude Code 等外部 Agent 对话中提供图片、用途与尺寸，确认场景方案；Agent 优先检索和复用可信素材，借助 Blender／脚本补制缺失物件，生成固定版本的 USD 场景包。Lab World 负责素材检索与获取、资产和场景管理、收到的制作摘要、验证及运行。已导入场景可以离线使用，新制素材可以被之后的场景检索和复用。

首期以 NVIDIA SimReady 为在线来源，新制素材以布景和静态物件为主。机器人、夹爪、设备行为与控制程序复用可信版本，不把本工作扩大为新机器人动力学建模、接触抓取控制器或训练交付。

典型演示：用户要搭建一个试管转运工作区。Agent 找到可信 FR3、工作台和台车，发现六孔试管架缺失，按有依据的参数补制；在对话中确认灰盒后组装场景。平台若报告孔洞碰撞失败，Agent 在外部修正、提交新版本、重新验证，最终交付与需求相符的结果。

本期验收终点是可运行的新场景、可复用的补制物件，以及一次真实验证失败后的修复。保留真实 Blender、平台视口和 Newton CPU 检查；完整机器人抓取／离心操作与训练成功不作为本期门槛。与暂停中的 #18 独立：不以它为前置，不恢复其工作，也不追认其验收；之后可以复用本工厂。

## 2. 三个界面的责任

| 界面／角色 | 负责 | 与平台的边界 |
|---|---|---|
| 用户与外部 Agent 对话 | 图片、用途、尺寸、型号、澄清、灰盒确认、修改指令 | 对话和附件不自动同步；Agent 可明确提交摘要和产物 |
| Blender 与外部工厂 | Agent 经 MCP／脚本制作，或用户直接编辑；材质修整、布局、补制、导出 | 已保存的工作文件经导出与导入后，才成为平台新版本 |
| Lab World Web | 人的素材检索／获取、资产与场景管理、预览、版本、缺口、报告和运行 | 只读展示收到的制作摘要；只呈现实际收到或自身产生的状态 |
| HTTP／CLI／MCP | 为人和 Agent 提供同一套检索、估算、获取、导入、验证和运行能力 | 统一策略、稳定身份和明确结果；MCP 保持通用 |

**平台不提供**场景用途／尺寸填写表单、参考图上传入口、灰盒审批向导、建模参数、物体摆放控件或内置制作聊天。素材检索条件、版本选择、相机查看、重新验证和启动场景仍是正常平台操作。

平台不能推断外部进度。没有汇报时，显示“未收到更新”或保留带时间的上一份记录。外部“已制作”与平台“已验证”是不同事实，前者不能覆盖后者。外部对话中的布局确认不增加平台 Approval Gate 类型，也不能充当预算调整或设备动作的审批。

## 3. 范围与既有契约

包含：统一目录与双语检索、精选来源准入、按需获取和适配、独立缓存、外部场景工厂、Blender 桥接、外部 Agent 的平台 skill、提交摘要与结果观察、端到端验收。

首期不包含：Web 场景编辑器、多用户远程库、全互联网素材抓取、所有 NVIDIA 包自动准入、公共素材托管／发布服务、自动修复任意物理机构、通用机器人规划器。图生 3D 为非关键道具的可选扩展，不成为基本流程依赖；启用前另定服务、许可条件和生成预算。

沿用既有契约：

- Asset 是不可变、带版本的物理素材，行为属于 EntityType、Binding Template 和 Device Program。
- USD 为规范格式，GLB 为平台视觉派生物；保持米制、Z-up、Prim Path／`entityKey` 约定。
- 场景引用明确的本地 Asset 版本；同内容重复导入复用版本，内容改变生成新版本。
- 设备操作继续经 HTTP 的统一 action pipeline，设备行为留在 `devices/` 与 `packages/programs/`。
- 不修改空间协议、录制格式或旧录制含义。旧场景与录制仍按原版本使用。
- 新接口采用增量扩展，保留现有本地库列表、描述、导入和 CLI/MCP 调用的兼容行为；实现时验证真实消费者。

## 4. 领域对象与身份

| 对象 | 含义和身份 |
|---|---|
| External Asset Catalog 条目 | 外部来源中的候选；包含 provider、上游 package ID、固定 revision 和来源证据；不是已安装 Asset |
| Source Package | 原始文件及所需依赖、许可证和元数据；进入独立原始缓存 |
| 本地 Asset | 适配、导入后由库返回的 `<kind>/<name>@<rev>` 与 contentHash |
| Acquisition（获取记录） | 一次可观察、可取消、可重试的获取；绑定源 revision、适配配方版本、预算与结果 |
| Scene Director（场景构建 Agent） | 在外部对话中组织场景需求、素材选择、制作与交付的 Agent 角色 |
| Scene Draft | 外部工厂中的可编辑草稿、假设、布局及缺口；不等于发布的 Scene Version |
| Scene Version | 固定 Asset 引用、布局、绑定、示教和仿真设置组成的不可变包 |
| Authoring Report（外部提交记录） | Agent／工厂明确上报的摘要、预览或进度，带来源、时间及所指对象 |

上游 revision、适配配方版本和本地版本号分别记录。相同源数据经新配方处理可能形成新内容；已经存在的相同内容继续复用本地版本。目录条目列出对应的已安装版本，不能以“最新”掩盖版本资格差异。精确版本查询必须返回该版本。

## 5. 人与 Agent 的检索

### 5.1 共用行为

统一入口覆盖本地库和已索引在线目录，支持 `all / local / online`。可检索范围与“一键获取”准入名单分开；未准入条目显示原因。首期支持中文、英文名称／别名和自然语言用途描述，并可组合明确条件。

请求包含自然语言 query、scope、类型明确的 filters、软偏好 preferences、排序、分页大小和游标。关键词／精确 ID／双语别名与语义召回共同发现候选；硬条件独立执行，相关性不能放宽条件。“小”“适合实验室”等只作软偏好，不能自行变成数值保证。自然语言解释与显式条件冲突时，返回可纠正的说明。

SF1b 已确认的首期范围：在线关键词没有候选时才进行 CPU 语义召回，不重排已有合格关键词结果；`local` scope 使用本地关键词／别名检索。真实模型的质量证据与明确标注的 CI 语义替身分开。

条件包括来源、本地状态、类别、物理尺寸、来源包大小、许可准入、布景／静态碰撞用途和获取资格。尺寸、网络传输大小、原始文件总量、落盘占用分别定义；单位明确。未知属性不能当作零、false 或满足条件。调用方可明确要求近似候选，但必须单列其不满足／未知条件。

### 5.2 内容与结果

精选目录补充经核对的双语名称、简短描述、别名、用途标签与预览。每个属性保留依据：上游声明、精选编辑、实际提取／测量、平台验证或未知。包名、生成的描述、SimReady 标识不能被当作碰撞或任务能力证明。

候选至少返回稳定引用、源 revision、对应本地版本、简述、预览、已知尺寸／字节数、许可决定、用途验证、获取状态、匹配理由、未知项和证据／详情入口。响应说明 interpretedQuery、appliedFilters、目录快照、覆盖范围、索引时间与下一页游标。“无匹配”仅指本次索引范围。

默认 10 条、最多 50 条，精简搜索响应上限 32 KiB；截断须有继续读取方式。游标绑定查询、条件、排序和目录快照；过期或快照不可用时明确要求重查。详情沿用有界摘要及按文档版本分页，不能要求 Agent 先拉全量目录。

### 5.3 两种使用方式

- 人：搜索框、类别浏览、缩略图／列表、可见的条件与匹配理由、详情比较；URL 可表达查询状态。零结果解释原因并提供可主动选择的调整，不偷偷放宽。
- Agent：参数 schema 明确描述枚举、单位、边界、未知值和输出结构；CLI 帮助、HTTP 与 MCP 共用行为。search → describe → estimate → acquire 可完成候选筛选与获取；不需要 shell 扫库、浏览器抓页面或下载主文件来读取已知元数据。

语义索引优先选本机 CPU 可运行的多语言方案，记录模型和索引版本；具体引擎由实现验证选定，不预先绑定向量数据库。检索不依赖 Space 的 GPU 服务或付费推理。已缓存目录断网仍可读，并标明新鲜度；在线可达性在获取时核实。

### 5.4 检索验收

- 固定至少 100 条有代表性、包含相似干扰项的记录；40 条中英文查询，各 20 条，覆盖精确名称、别名、用途、条件组合、未知与零结果。每种语言至少 8 条查询预先冻结为保留集，不参与调优；查询、划分、相关性标注与目录快照一起版本化。
- 独立 Agent 提供初始相关性标注，用户抽查并裁决争议；相关指满足查询用途且不违反明确硬条件。最终验收前冻结标注。保留集上有相关候选的查询中，至少 90% 的前五项包含相关结果；中文、英文分别报告成功数、分母及调优集／保留集结果，零结果案例另报，不以小样本宣称统计保证。
- 有效精确 ID／版本定位正确率 100%；硬条件验收用例 100% 不把不满足或未知当作通过。
- 同一快照与条件下，Web、CLI、MCP 的候选身份与资格判定一致；分页可继续且不混淆版本。
- 在仓库规定的 Linux／WSL 基线机上，固定模型、千条记录、模型已加载时，检索 P95 ≤ 2 秒；冷启动另报，证据记录 CPU、模型及索引版本。
- 固定 Agent 版本，仅给平台工具和任务描述，完成筛选、比较、估算与允许的获取；含无合格候选的正确退出。真实语义／Agent 评估与 CI 的确定性接口测试分开。

基础检索先交付精确身份、关键词／双语别名、硬条件和 describe／estimate；语义增强单独交付，获取能力不等待它。真实 Agent 验收在相应实施票中先列模型、凭据引用、Token／费用上限与清理方式，再取得授权；本规格确认不授权付费调用。

## 6. 来源、许可与按需获取

### 6.1 第一来源

接入 `nvidia/simready-assets`，从完成逐包许可与适配检查的精选项提供一键获取。固定 HF commit 和包身份，按所需清单解析文件与依赖；LFS 文件获取实际内容，不能把指针当资产。Space 可以作为上游浏览链接，不作为运行依赖或长期稳定 API 的假设。

优先候选为回收容器、桶、纸箱、工具台车、桌子：`container_recycle_square_blue_a02`、`bucket_utility_gray_a01`、`box_cardboard_a01`、`equipment_utility_cart_e01`、`desk_a01`。它们只是已发现的候选，必须经过实际适配与验证才能进入准入名单。

### 6.2 许可目标与证据

必须支持商用、修改、随场景分享；接受署名、保留许可／NOTICE 和修改记录。初期优先 CC0、CC BY 4.0 与已核实的宽松附属文件许可。NC／ND 不符合目标；其他条款须明确审查，不能自动视为友好。

准入决定绑定来源 revision、适用文件范围、许可文本／摘要哈希、来源、署名及义务。源内容或许可更新后重新判断。包许可、MDL 等附件许可、Space 代码许可和 Blender MCP 软件许可分别处理。

文件清单之外的 LICENSE／NOTICE 也要保留；必测“LICENSE 不在 BOM 内”的案例。第三方素材经修改仍保留原许可与来源；自制素材不自动改成 CC0，也不自动公开发布。自制或混合来源的许可未明确时，显示缺口，不伪造许可通过。

### 6.3 预算和自治

| 默认项 | 上限／要求 |
|---|---|
| 单个 Source Package | 512 MiB，包含所需依赖和许可／元数据的原始逻辑字节量 |
| 单个适配成品包 | 512 MiB，独立于原始包计算 |
| 一次获取批量 | 2 GiB 原始逻辑数据；去重／缓存和实际网络传输分别报告 |
| 原始缓存 | 10 GiB；不包含不可变的已导入版本 |
| 并发获取 | 全网关最多 2 个，人和 Agent 共用额度 |
| 磁盘余量 | 为原始、临时与成品空间预留后，仍保留 10 GiB |

限额可配置。Agent 可在已准入来源、许可和预算内自行检索、获取、适配与导入，无需逐项确认。超限返回估算与原因；人通过明确配置或适用的人工机制调整，Agent 不自行提高上限。未知来源／许可保持缺口。下载授权不包含付费图像／3D 生成。

估算分别列出文件总量、缓存复用、需传输数据、临时空间和成品上界。不能给出有界估算的适配不自动执行。空间预留跨并发共享，实际增长也受限；同一记录的重试／重启不能重置已使用预算或重复分配剩余空间。

### 6.4 获取生命周期

公共请求使用受支持的目录引用，返回持久获取 ID；不接收任意网关路径或任意 URL。状态覆盖 queued、downloading、preparing、validating、importing，以及 succeeded／failed／cancelled。允许读取进度、取消、重试，返回固定源版本、估算／实际用量、问题与本地结果。

校验每个文件和依赖闭包，缺失、哈希不符、不可支持的材质或物理属性明确失败／报告缺口。已核实下载可复用；重启后恢复安全步骤或显示 interrupted 并允许重试。半成品不出现在已安装版本中。取消必须区分尚未发布与已经导入成功，不能借取消删除已发布版本。

准备后的包复用现有不可变发布事务。现有 128 MiB tar 上传、256 MiB 解包限制不足以覆盖该目标，获取切片必须交付有界、仅消费服务端自有暂存的内部导入路径，仍执行同一校验、版本分配和原子发布；不以暴露任意路径绕过限制。

原始缓存仅清理未被使用的项，可按最近使用时间回收。导入产物必须自包含，不能继续引用源缓存或远端；清理缓存和断网后仍能使用。新 acquisition、新 import、用途验证通过是三个不同事实。

## 7. 素材适配与可用性

平台完成已支持的确定性依赖整理、路径／单位规范化、USD 结构适配、GLB 派生和验证；模型修补、缺失碰撞制作、关节／行为设计由外部工厂处理。

布景可用和静态碰撞可用分别报告。缺可信碰撞的视觉素材可明确作为 Dressing；物理用途要求相应证据，不能静默降级。缺质量、关节或动作时不自动猜测填齐；估算数据须按既有规则标明依据与警告，不能冒充真实测量。

规范输出仍为 `/Asset`、米制 Z-up、包内依赖或固定 library 引用，以及本地 GLB。保留原始来源、实际导出文件哈希、配方／工具版本、变换和近似记录。既有资产的验证结果不能自动移植到修改过的几何上。

- **布景可用**：S1、S2、S4、S6 通过，且平台能加载 GLB。
- **静态碰撞可用**：布景可用，具有碰撞体，并且 Newton P1、P3 通过。该标签不证明任意装配、机器人操作或完整任务成功；其它适用检查的失败仍保留，场景启动沿用既有完整判定。
- **封孔案例**：在验收场景中把真实试管放进孔内，通过现有场景级 P2／P3 检出沉降或穿插问题；外部修复碰撞后以新版本重验。首期不新增通用素材插入／净空检查。

SimReady 首期固定选择 Newton 物理变体，转换到规范根并记录所选变体；无该变体时明确报告缺口。上游 profile／feature 验证结果（包括失败项）仅作为上游声明，不能替代平台报告。GLB 派生只覆盖受支持的网格和 UsdPreviewSurface 回退材质，优先复用成熟工具，不向网关引入 Blender；仅有 MDL 的材质报缺口。允许确定性贴图降采样并记录近似，超出网格预算交外部工厂处理。

实际文件引用必须解析到固定包内的依赖闭包，输出使用安全相对路径。逃逸包根的路径、不能安全规范化的绝对／反斜杠路径、远端引用或清单外 MDL 依赖均明确失败或报缺口。元数据中的 Windows `asset_location` 可原样作为来源证据保留，不能当作网关文件路径执行。

## 8. 外部 Scene Director 工作流

### 8.1 对话与灰盒

在 Claude Code 等外部对话收集用途、图片／图纸、房间尺度、已知尺寸、机器人与末端型号、接触／操作对象、净空、固定约束、视觉偏好和预算。事实可从官方和库中查到时自行调查，只追问无法核实且影响交付的内容。

区分真实复刻与新设计：前者需要图纸／测量依据，后者可以用明确设计参数。单张照片不构成关节、质量或精密尺寸的证明。关键未知保持可见，独立工作继续推进。

Agent 形成素材需求清单和带尺寸的灰盒，提供俯视／空间视角、假设及缺口。用户在原对话中确认或要求修改，不到平台重复确认。确认后 Agent 在约定范围内自主细化；改变核心型号、关键尺寸或布局时回到原对话说明影响。

### 8.2 复用与缺失素材

顺序为本地可信 Asset → 官方／已准入在线素材 → 合法衍生 → 参数化／Blender 补制 → 可选非关键图生 3D。

机器人、机械臂、夹爪优先精确型号的官方或已验证资产。缺失时报告、寻找可信来源或请用户选择替代，不按照片自建外观模型冒充该设备。

规则壳体、柜、箱、支架等优先 bpy／参数化制作；任务关键夹具、孔位等按设计或测量依据制作碰撞。软质复杂外观可选择已有素材／Blender 修整，图生 3D 的服务、许可和预算另定。整间场景不生成一个不可拆分的大网格。

灰盒占位件允许用于布局沟通，但不计入任务完成。形体、PBR、碰撞、质量／惯量、关节／站点与行为分别检查：看起来有孔不证明碰撞留孔，离心机外壳不提供开盖或旋转动作。

### 8.3 Blender 控制层和工厂产物

复用 [MCP for Blender](https://github.com/ahujasid/mcp-for-blender) 的脚本执行、场景查询与视觉查看能力，不另造一套 Blender 控制协议。固定并配对 server/addon 版本，验证所选 Blender 版本。项目脚本负责资产版本／实例映射、稳定 entityKey、布局提取、补制、USD／GLB 输出及来源记录。

脚本放在本仓库的独立工厂目录，作为平台外的制作工具；网关运行时不导入 bpy。纯 Python 部分进入 GPU-free CI，真实 Blender 部分单独验收。可重跑步骤通过 Blender 后台 Python 脚本入口执行；MCP 用于交互查看和临时操作，开启 `BLENDER_MCP_SAFE_MODE=1`，addon server 仅在制作期间运行。该设置不是任意代码的安全沙箱。

支持清单固定 `DISABLE_TELEMETRY=true`，内容遥测关闭，未准入的第三方来源／生成器关闭。Platform Skill 将目录及第三方文本当作数据，不作为脚本执行指令。

Blender 中的人类对象名称不自动等于 entityKey。已有机器人／物理 USD 保留原包；Blender 用视觉参考摆放，工厂提取资产引用和整体位姿，由 OpenUSD 写组合层。Blender 导入再导出不被假定为层、变体、材质和物理语义的无损往返。改网格、改尺寸或缩放物理机构需衍生素材与新验证。

原始 `.blend`、参数、种子、脚本和手工工作版本留在工厂侧。可自动化步骤可重跑，手工修改以保存文件为依据。装饰随机化固定种子，不随机挪动机器人、夹具、教点和任务布局。包围盒／射线可辅助摆放，但不代替 Newton 和实际运动检查。

程序化材质、体积光、玻璃和 IES 按平台支持程度派生／烘焙，记录近似与缺口。最终视觉检查在平台真实视口完成，不以 Cycles 图片代替。MCP 的 viewport 查看可能要求实际视口和 GPU，不作为 GPU-free CI 前提。

MCP for Blender 自带的其他素材来源／生成器不自动获得本平台准入；NVIDIA 获取继续走共享许可、版本和预算路径。

## 9. 组装、提交与修订

新制素材先导入，用实际返回的 Asset 版本组装场景，不猜版本号。场景包沿用 `scene.yaml`、`stage.usda`、`devices.yaml`、`locations.yaml` 和预览。新包不提供伪造的 `validation.json`，平台生成报告。

外部提交至少有：稳定 submissionId、source／sourceVersion、reportedAt、服务端 receivedAt、被引用的外部 draft ID 或精确 Asset／Scene Version、适用内容哈希、摘要／已知缺口、附属产物引用。重复提交幂等。没有已导入对象时只能关联外部草稿，不能声称某个未存在的版本已验证。

摘要上限 64 KiB，在 Web 按纯文本呈现；附属产物只保存引用，不将报告接口扩成附件存储或任意文件读取入口。

页面区分“外部汇报”和“平台执行／验证”；旧汇报不能覆盖较新产物状态。外部对话的确认可以是带来源的摘要，不是平台重新审批的按钮。本文只要求必要的状态与产物接收，不引入平台自动执行整份制作计划。

修改意图通过原对话给 Agent，或由用户在 Blender 直接修改。工厂检测其输入版本／草稿是否已变，发生冲突时报出，不无声覆盖。首期不做隐式双向实时同步。

**必须保持的案例**：平台 v2 中台车位移为 0.00 m；Blender 工作文件已改为 0.20 m，但尚未提交，平台仍显示 v2 的 0.00 m。导入后生成 v3，报告为待验证；重新验证通过后才可按当前版本启动。旧 v2、其报告、正在使用它的内容及旧录制不被重写。

## 10. 平台界面与 Agent 能力

平台页面围绕素材库、场景详情、资产依赖、版本、验证报告和接收／执行记录组织。已有简报仅只读显示来源与时间。用户可以复制失败摘要给原对话中的 Agent；“复制”不自动向外部发消息。平台不出现几何修复按钮或假装能观察未提交的 Blender 编辑。

结果展示采用原型 **A：场景优先**。沿用现有框架，以已接收版本的场景为主区域，版本、固定素材依赖与平台验证报告放在旁侧，接收记录放在详情中；不将原型播放器或 A/B/C 切换器变成产品功能。在线检索、获取记录与接收记录的页面契约同步登记在 Web 规格中。

能力按一个 HTTP 实现提供给 Web、CLI、MCP：

| 能力 | 结果／行为 |
|---|---|
| search / describe | 有界候选、证据、未知项、固定身份及分页 |
| estimate | 源 revision、文件与许可清单、缓存／下载／空间、资格与预算决定 |
| acquire / status / cancel / retry | 持久获取记录、阶段与结果，不留下已安装半成品 |
| import / validate / launch | 复用现有素材／场景入口、不可变版本与平台报告 |
| submit / read authoring report | 明确来源的外部摘要、所指草稿／版本、时间与缺口 |

具体新增路由和命令拼写由实现按现有约定确定；上述语义和兼容要求固定。MCP 不提供策略／审批绕过。外部场景构建 Platform Skill 在真实已实现入口上编排对话、检索、制作和交付，不虚构命令，不要求用户用平台表单重走流程。

## 11. 验证与交付阶段

分开回答四个问题：候选是否匹配、素材能用于什么、场景能否启动、本次任务是否成功。结构／物理检查、P6 端点、运动轨迹和完整操作结果不能互相替代。需要操作时复用既有受支持程序，并检查实际结果；当前 FR3 教点工具不被扩称为通用规划器。

实施票作为 #133 的 sub-issues，真实阻塞用 native dependencies；各票维护实现与验收证据。沿用原规格，不另建一份冲突的总规格。

| 阶段 | 依赖 | 可演示的交付 |
|---|---|---|
| SF0 来源与工厂可行性 | 既有素材／场景基础 | 五个候选逐项给出实际适配结果、许可／依赖与大小边界；至少一个走通规范 USD/GLB 导入验证；固定 Blender/MCP 版本与配置、Newton 变体处理，形成受限支持清单 |
| SF1a 基础目录与双语检索 | SF0 | Web／CLI／MCP 精确 ID／版本、关键词与双语别名、硬条件、describe／estimate 和有界分页 |
| SF1b 语义检索与质量验收 | SF1a | 共享 CPU 多语言召回、真实语料／保留集和 §5.4 检索质量／性能证据，不阻塞获取 |
| SF2 获取、适配与入库 | SF1a | Web／CLI／MCP 按预算获取，支持进度、取消、重试、幂等、来源记录和离线使用；解决现有导入大小限制 |
| SF3 场景工厂与 Blender 桥接 | SF2 | 复用可信素材、补制一个静态物件、导出场景；人工 Blender 编辑与 Agent 脚本均产生正确引用与位姿 |
| SF4 平台结果管理 | SF2 | 按本规格的提交数据接收只读摘要，展示来源／时间、版本／依赖／报告；未提交编辑隔离和失败上下文回传；不必等待 SF3 实现完成 |
| SF5 外部 Scene Director 与端到端验收 | SF1b、SF3、SF4 | 从外部对话出发，经灰盒确认、补制、导入、失败修复，交付可运行场景及可复用素材 |

每阶段是一条命令能启动或浏览器能看到的垂直交付，包含适用的公开接口与验证。图生 3D、更多来源和 Web 编辑器不进入上述必需依赖。

SF1b 验证真实语义检索及三端一致性，不要求尚未交付的获取能力；§5.4 的真实 Agent 比较、估算及获取综合旅程由 SF5 验收，避免隐式依赖或重复付费运行。

主要测试接缝沿用公开 HTTP 旅程：搜索 → 估算 → 获取 → 精确本地版本 → 验证 → 引用／启动，在来源传输边界使用小型确定性包。CLI／MCP 用真实入口验证与 HTTP 同值，不重复搭建业务测试层；浏览器验证检索获取、场景优先结果页、失败报告及未提交修改隔离。只检查外部行为、持久结果和兼容性，不绑定内部类与调用次数。先例是已有库描述跨传输测试、不可变导入／重启测试及库页面旅程。

CI 使用自制合成夹具和语义替身，不带 NVIDIA 素材、模型权重、实时网络、付费调用或 Blender。每票注明归属现有 CI lane 与预计新增耗时；遵守每 job 中位数目标 < 4 分钟、10 分钟 timeout，main-push 周中位数 > 5 分钟时进入维护。真实素材适配、语义模型、Blender、Newton CPU 和真实 Agent 的证据分别保留，不由替身测试代证。

## 13. 已知事实与风险控制

现有实现包含不可变导入与 S/P 验证、统一检索／获取、CLI/MCP、独立 Blender 工厂与 USD 组合。具体支持范围在 `factory/support.json` 与 Scene Factory 指引中维护；自动碰撞拟合和任意机构修复不属于已交付能力。

精选目录记录经核对的双语描述、尺寸、许可与用途证据；上游轻量 JSON 的包身份、声明许可、BOM 与 root USD 不自行证明这些属性。尚未覆盖的元数据保持未知，不能让语义模型填成“已验证事实”。

抽查包的大小是源文件总量，不是 ZIP 体积。约 497 MiB 的 CT 包、402 MiB 的输液架已超过旧解包上限，且 Blender／GLB 转换可能产生更多临时数据。SF0 先测实际边界，SF2 实现受限导入；不靠无上限放开上传解决。

Blender USD 往返存在层／变体／材质边界；MCP 提供控制能力，不补足物理保真。以保留可信原包、OpenUSD 引用和实际 Newton 检查控制风险。真实任务失败应诚实保留，不能降低物理或任务门限来完成这张规格票。
