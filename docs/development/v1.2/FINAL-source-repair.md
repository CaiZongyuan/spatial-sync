## Behavior and ownership

Session resolves and validates a subscription before changing the source. Its periodic interest is the union of accepted fixed scopes; no observers select zero rows. All and viewport select every declared Body so moving entrants remain discoverable. A source interest change executes at a safe Runner boundary and returns one actual full sample S. Existing observers receive a reliable regular full keyframe, then the requesting observer receives its correlated ack and scoped snapshot. Command delivery remains frame → ack → state, with complete source captures regardless of current periodic interest.

`SpatialSource.latest_frame()` may be a partial periodic sample. `snapshot()` returns a single actual full capture; RUNNING captures a new sequence, while PAUSED may return the last complete command sample with its original sequence/time. `set_interest(ids | None)` returns the complete barrier and installs periodic targets. Both local and remote implementations must enter transition before sending the mutation. `SourceFrames` discards transition and ≤S periodic packets before membership checks, requires exactly the installed periodic set afterward, and validates control samples against all Manifest Bodies. The local adapter also clears bytes already queued on the independent frame pipe while atomically installing the new interest. No held row is combined with fresh rows and labeled as a new complete sample.

HTTP `/snapshot` calls the async full capture without holding Session's command lock. It validates source/revision/offset after the await and preserves the returned sample's own seq/simTime even when a newer periodic sample was already observed. `/pose` requests no source control operation: it may synchronously cache a complete `latest_frame()`, then serves the most recent retained complete sample; newer partial samples cannot replace or relabel it. Unknown entities remain 404 and a missing complete sample remains 503. Initial interest barriers are validated before exposing a replacement revision. An invalid candidate therefore leaves the prior valid Manifest and complete cache available. Session keeps a distinct complete cache; FAILED/STOPPED HTTP and late/reconnected observers use its original sample metadata. They do not mutate a failed source's interest or disguise a failed state.

Snapshot is read-only: timeout becomes HTTP 504 `query_timeout`; a same-union subscription snapshot timeout returns a correlated `session_not_ready` and leaves its previous scope/Session live. Local late snapshot replies are drained and may refresh the honest complete cache. A failed/unknown-outcome interest mutation explicitly fails the source/Session. Rejected scopes cannot alter the union.

TransformExtractor has one model-capacity pair of reusable staging/readback slots, variable per-capture real body indices, and one FIFO model-wide PoseFilter. CUDA launches/copies exactly the selected row count. Host/device index arrays remain owned by their job until CUDA completion and callback completion. Invalid pose fallback and warning/counter indices refer to the actual model Body, independent of compact slot order. Metrics report actual last-capture Bodies and `count × 28` bytes (seven float32 pose components, excluding stream IDs/header). Full recovery/command captures legitimately report full readback even when configured periodic `gatherBodyCount` is narrow.

`SourceInfo.shapeCount` comes from real `model.shape_count`, reaches Manifest/Session stats and Diagnostics. Synthetic leaves it unknown. Runner emits its own monotonic heartbeat sequence and relative receipt age during RUNNING and PAUSED. `RunnerHeartbeat` relays age without rejuvenating a duplicate sequence, avoiding cross-host absolute-clock subtraction. Producer loss makes Runner heartbeat unavailable; Gateway's independent `server.heartbeat` remains visible. Synthetic shows `—` for Runner heartbeat and Shapes.

TLS implementation is owned by the separate remote repair slice, using the shared `SourceFrames`/`RunnerHeartbeat` contract. That author exclusively owns `remote.py`, `remote_server.py`, `remote_source.py`, remote tests and `FINAL-remote-repair.md`. This source candidate intentionally does not claim remote integration before that slice is merged; the old `test_remote_runner.py` is excluded from the candidate's broad Gateway run for that reason. PM must integrate both and refresh remote verification on the integrated revision.

## Change impact and bounded simplification

Inspected the fixed baseline through the candidate, all task-owned untracked files, and concrete source consumers: local Runner/adapter, Synthetic, Session startup/reload/subscription/removal/command/HTTP/cache, generated protocol types and Diagnostics. TLS contract and source helper ownership were explicitly handed to the remote author. No new dependencies or alternate authority were introduced.

The bounded simplification keeps membership/barrier/full-cache validation in one shared adapter helper, heartbeat age in one shared helper, and a single model-indexed filter. Session reuses one complete-sample predicate for candidate and current revision checks and caches the Manifest body-ID set instead of rebuilding it for every partial frame. Startup/reload/event tasks, independent Gateway heartbeat and shielded WS cleanup preserve the lifecycle author's ownership. No broader Session redesign was justified; complete-cache ownership and separate command/read-only timeout policies are required distinctions.

Per-capture CUDA index arrays are retained correctly but currently allocated per capture; readback-byte reduction alone does not prove a total speedup. No old performance comparison was rerun or relabeled. No remote-host timing/clock evidence or GitHub CI result is claimed here.
