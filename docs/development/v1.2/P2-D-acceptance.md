# P2-D remote Runner acceptance

The user authorized the complete v1.2 specification. P2-D replaces the Gateway-to-Runner transport while preserving the existing HTTP/WS behavior and the SpatialSource boundary. It does not authorize public deployment. The original Newton developer owns the implementation in a new issue worktree after an implementation slot is released.

The transport must carry bounded typed control data and compact NSYN frames across a real network connection. Local multiprocessing pickle is an implementation detail of trusted local Pipes; it must never become a network decoder. Validate operation names and payloads, frame sizes before allocation, credentials before engine startup, and finite/valid schema values. Binary mesh replies need an explicit bounded representation. Preserve independent periodic latest-only and reliable control ownership, command frame/ack/state ordering, bounded pending work and slow-peer failure isolation.

Provide explicit authenticated TLS configuration with certificate verification, finite connection/handshake/read limits, and a loopback development default. Secrets and private keys do not belong in committed fixtures or logs. Tests may create disposable credentials/certificates. Do not expose a public listener, disable certificate verification, or start an unconfigured remote source implicitly.

Gateway receipt time replaces remote Runner sampleTimeMs for both periodic frames and reliable snapshots/command frames. Ready and source metadata declare the clock source. Epoch, source sample seq/simTime, global Session allocation and delayed-control metadata remain honest. Existing local clock behavior is retained.

Demonstrate a real loopback server/client using the production transport and the same public Gateway endpoints: start, complete Manifest/snapshot, periodic frames, pause/step/reset/resume, joint/mesh queries where available, two observers, reload, remote peer loss, API health/restart, timeout and close cleanup. Keep the mandatory gate free of Newton/GPU by using the existing source/test seam. Add a bounded optional actual Newton CPU journey to establish engine compatibility. Reject unauthorized connections, malformed/oversized/truncated input and untrusted certificates through actual transport entrypoints.

The developer supplies a clean frozen candidate, public launch commands, protocol/consumer impact note, bounded simplification, affected tests and real execution/cleanup receipts in P2-D.md. Final integrated gates and non-author Standards/Spec review remain PM-owned. Report real-network and deployment limits explicitly: loopback TLS proves a network boundary, not WAN latency or a deployed service.
