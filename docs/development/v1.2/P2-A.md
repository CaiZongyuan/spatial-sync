# P2-A — Binary Transform Stream

Implementation candidate: `b7cc387051405366087ab8667736f9be2f2ce682`. Original issue baseline: `8c2d367184fa3818c425ac359eabc3714c5ef936`; integrated MVP reference: `b76a782`. Independent review and root integration are owned by the PM and remain separate from this implementation receipt.

JSON remains the default. Open `/sessions/{sessionId}?format=binary` to opt in, or send `client.subscribe` with `format: "binary"`. The JSON subscription acknowledgement reports the granted format. Control, lifecycle, heartbeat and entity-state messages remain JSON. One connection pump writes both message types, preserving reliable frame → acknowledgement → state ordering, bounded queues and slow-client isolation.

The existing authoritative Python `FrameCodec` supplies the unchanged Protocol 1 NSYN format: 44-byte little-endian header and 32 bytes per body (`uint32 streamId`, seven `float32` values). Gateway encoding uses the session Manifest's numeric revision and global sequence; source-local IPC bytes are never forwarded blindly. Frontend `DataView` checks length, magic, version, kind, revision, count and timestamps before exposing typed-array views. Sequences exceeding JavaScript's safe integer range are rejected and counted. JSON and binary share the same epoch, recovery, interpolation and finite-pose ingestion rules. Binary ingestion creates no per-body temporary object/array. Scalar pose writes also remove the former JSON per-body slices; that shared improvement must not be attributed solely to binary.

## Evidence and measurement limits

Machine: Windows 11 build 26200, Intel Core i7-12700H (14 cores / 20 logical processors), 34,070,847,488 bytes installed memory. Python 3.13.14, Pydantic 2.12.4, NumPy 2.5.4, FastAPI 0.143.2, Uvicorn 0.54.0, websockets 16.1.1, Node 24.18.0, pnpm 10.32.1, Playwright 1.64.1, Chromium 156.0.8078.4. No Newton, Warp or GPU work is included in these stream measurements.

`tools/profile_stream.py` generates eight immutable, deterministic pose phases. Both formats consume the same validated templates and every decoded body ID/pose is checked against the frozen input with absolute tolerance 1e-6. [The oracle regression](../../../tests/unit/test_profile_stream.py) independently fixes the first row and proves that wrong IDs, positions and nonfinite values fail. Corpus SHA-256 values and package versions are present in each raw receipt.

Initial profiling preceded the optional WebSocket binary implementation. [Codec measurements](newton-p2a-evidence/baseline-codecs.json), with five warmups and 15 measured samples per case, found JSON encoding p95 48.68 ms versus binary 2.84 ms at 10,000 bodies. Both Python decode paths include Pydantic validation: binary parse/validate p95 was 16.27 ms versus JSON 14.24 ms at that size, so these results do not support a universal parser speedup. Payload sizes for the fixed phase were 577,262 JSON bytes and 320,044 binary bytes. The initial [actual JSON WebSocket pressure run](newton-p2a-evidence/baseline-network-10000-8.json) had gateway encoding p95 77.60 ms and 28–29 verified frames per receiver over 3.09 s, supporting the decision to implement binary.

The network harness runs the real Gateway/Uvicorn and separate spawned receiver processes for 1, 2 or 8 WebSocket clients. Compression is disabled at both ends. Source setup, downloads and a one-second warmup precede the measurement. Final gateway encode samples are cleared after warmup. Client timing includes parsing, array application and full pose verification; it is a Python receiver boundary, distinct from the browser experiment below. Receive counters start at the shared measurement signal and stop when the coordinator sets the stop signal after collecting Gateway statistics, so a few boundary/tail frames can appear; the raw counts and durations are reported rather than treating values slightly above 30 as a sustained rate claim.

| Bodies × clients | JSON verified frames / receiver | Binary verified frames / receiver | JSON encode p95 | Binary encode p95 |
| --- | --- | --- | --- | --- |
| 35 × 1 | 92 / 3.026 s | 92 / 3.032 s | 0.374 ms | 0.043 ms |
| 500 × 2 | 92 / 3.013 s | 92 / 3.032 s | 2.656 ms | 0.231 ms |
| 10,000 × 8 | 50 / 3.174 s | 91 / 3.016 s | 61.226 ms | 2.423 ms |

All final receivers reported zero incorrect outputs. Final latest-slot drop deltas were zero; source/latest-frame coalescing and missed publication opportunities are not equivalent to a measured network packet loss count. At 10,000 × 8, receiver parse/apply/verify p95 was 19.41–20.84 ms for JSON and 0.96–1.23 ms for binary. Aggregate received payload was approximately 72.75 MB/s and 77.26 MB/s respectively because binary delivered more useful frames. These are short, local single-machine stream results; they do not measure real-network capacity, physics, GPU readback, renderer FPS, or a cross-hardware 30 Hz guarantee.

The [pre-cadence equal-work JSON](newton-p2a-evidence/json-network-equal.json) and [binary](newton-p2a-evidence/binary-network-equal.json) runs separately observed 28 versus 54–55 verified frames per receiver in about three seconds, with encoding p95 76.41 versus 3.24 ms. Both used the same original scheduler. Their accumulated encode samples include warmup. Do not compare those runs directly with the final scheduler as a codec-only speedup.

## Bounded scheduling diagnosis

The integrated tiny-scene observation of roughly 20 Hz was a separate bottleneck. One [bounded timer probe](newton-p2a-evidence/timer-probe.json) found that a requested 4.167 ms sleep woke at p50 15.60 ms, while a relative 33.333 ms sleep produced 21.46 Hz (p50 interval 46.60 ms). The same 33.333 ms target anchored to deadlines produced 30.005 Hz. No global timer setting was changed.

Source publication and client sending now preserve their deadline cadence and skip missed slots. A coarse 64 Hz clock regression checks the source's 30 Hz target without historical catch-up bursts. An initial deadline-only [35 × 1 JSON run](newton-p2a-evidence/json-network-35-1-deadline.json) advanced the source by 90 frames but the Gateway by only 77 over 3.03 s, exposing coalescing from source/monitor phases. The PM authorized one bounded follow-up: the monitor polls at at most 10 ms, still publishing only new sequences and retaining the pump's granted-rate cadence. The final 35 × 1 JSON run advanced both source and Gateway by 90 frames; the proportional cases above used that identical scheduler for both formats. No callback redesign or further timing tuning was added.

## Actual browser boundary and journeys

`tools/profile_browser_stream.ts` downloads Python/gateway-encoded fixtures through the test-only `demo_app` factory and imports the production PoseBuffer through Vite. Header sequence/time patching, Manifest setup, corpus download, twelve warmup samples and the complete per-body pose oracle are outside timing. Forty ordinary transform frames follow one untimed recovery snapshot for each format, with two passes in reversed format order. Every sample must be accepted and all resulting body poses must match; repeated snapshots or discarded frames cannot count as work.

[Chromium results](newton-p2a-evidence/browser-codecs.json) time JSON.parse → PoseBuffer against binary DataView/typed-array views → the same PoseBuffer. At 500 bodies p95 was 0.2 versus 0.1 ms, at 2,000 bodies 0.5–0.6 versus 0.2 ms, and at 10,000 bodies 2.5–2.6 versus 1.0–1.1 ms. Small-case zero values reflect approximately 0.1 ms clock granularity, not free work. All samples had zero invalid, skipped or discarded frames. Rendering, network receive and React work are excluded.

`tests/e2e/binary.spec.ts` uses actual production SyntheticSource, Gateway and Chromium, alongside the existing JSON workbench journey. It checks real NSYN binary WebSocket frames and a separate default JSON browser; all 24 body poses against the independent HTTP snapshot; pause, step and epoch reset; paused same-sequence reconnect and visibility recovery; and scene replacement with the new revision/global sequence. Commands remain text JSON. The final [wire/client receipt](newton-p2a-evidence/browser-wire.json) records 58 observed binary frames, 58 observed JSON frames, three JSON commands, identical final sequence 126, and zero binary errors. Counters are sampled asynchronously, so the JSON client can consume a subsequent frame before the wire observer count is read. The [screenshot](newton-p2a-evidence/binary-workbench.png) was visually inspected; software rendering FPS is outside the stream claim.

## Validation and impact

Passed: `uv run --no-sync pytest tests/contract tests/gateway tests/unit -q` (115); `pnpm test:web` (55); `pnpm test:protocol:ts` (6); `pnpm build`; owned Python Ruff; standalone browser-harness TypeScript check; deterministic protocol regeneration plus `export_schema.py --check`; and actual `binary.spec.ts` + `workbench.spec.ts` (2 tests, 24.5 s). [Validation receipt](P2-A-validation.txt).

Bare `pytest -q` was attempted and failed during optional simulation collection because `tests/sim_runtime/test_mesh_export.py` imports Warp before its optional Newton skip. This isolated environment deliberately has no simulation extras. No simulation test pass is claimed; the PM's integrated environment must cover that unchanged consumer. Earlier harness-only failures were corrected: a reload oracle now permits legal lifecycle state before subscription acknowledgement; the standalone Node harness uses an async entrypoint compatible with the repository's CommonJS package mode; and the e2e test's type context/serialized node payload is explicit. Those failed attempts did not produce performance claims.

Impact trace: Python Subscribe/SubscriptionAck schema → generated schema/types/fixtures → Gateway per-(scope, format) encoder and sole sender → SessionClient ordered receive chain → common PoseBuffer → existing renderer/inspector. Missing format preserves JSON behavior, and legacy acknowledgement without format falls back to JSON in metrics. Cross-language fixture, malformed-header tests, mixed observers, reload metadata, timeout isolation and actual browsers cover these boundaries. No external consumer beyond the repository was available to test. Float32 position/rotation precision follows the wire contract; the fixture's 1e-6 absolute comparison is not a universal bound for arbitrary coordinate magnitudes.

The bounded simplification pass inspected the full task-owned change range and immediate consumers. It centralized ingestion semantics and scalar pose writes, restored repository quote style, and kept validation, endian fallback, recovery distinctions, queue limits and writer ownership. Further helper/generalization changes did not offer a concrete maintenance benefit. Future delta/keyframe kinds 3–5 are reserved for P2-B and are deliberately rejected here until implemented there.

All owned API 8005/web 5185 listeners and benchmark child processes were stopped. No GPU context or database was retained. Benchmark data, screenshot and event journal remain local in this repository.

## Reproduce

From the worktree, install the default Python/frontend dependencies. Run `uv run --no-sync python tools/profile_stream.py codec --iterations 15 --output .scratch/p2-a/codecs.json` or `... network --count 10000 --clients 8 --format binary --output .scratch/p2-a/network.json` (replace `binary` with `json` for the comparison). Keep all arguments and environment equal; run formats sequentially.

For browsers, run `uv run --no-sync uvicorn tools.profile_stream:demo_app --factory --host 127.0.0.1 --port 8005`, and Vite on 5185 with `SPATIAL_API_URL=http://127.0.0.1:8005`. Set `SPATIAL_WEB_URL=http://127.0.0.1:5185` and the same API variable before `pnpm --filter @spatial-sync/web exec playwright test binary.spec.ts workbench.spec.ts`. Run `pnpm exec tsx tools/profile_browser_stream.ts` from the worktree root for the browser boundary receipt. The corpus endpoint belongs only to the test factory. Stop both services afterward.
