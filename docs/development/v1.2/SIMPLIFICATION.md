# Integrated simplification survey

Baseline: `633735534aa05376138904582ebb7712a0ea19c9`. Current inspected integration: `389687587435150665d10b3e0d726943c661f15d`, including the complete Source `ba48bc5` and TLS `5d7292d` repairs, P2-C `0cf3e25`, P2-D `15c2bcc` and static cleanup `f9eb15f`. The survey includes committed/new runtime, generated consumers, tests, public HTTP/WS, browser diagnostics and the extraction profiling tool; final execution and both independent review results are recorded separately. This is an epic survey, not a claim that unfinished work was inspected.

| Candidate / boundary | Evidence and maintenance effect | Decision |
| --- | --- | --- |
| JSON and binary pose application | P2-A routes both representations through PoseBuffer.ingest/writePose. This removes the per-body JSON slices and duplicate interpolation/recovery semantics. Header decoding remains representation-specific. | Already simplified and covered by both consumer tests and real browsers. Retain endian, finite-pose, epoch/revision and recovery distinctions. |
| Replace SpatialSource with direct Newton calls | main/session_manager consume sources/base.py while NewtonSource owns spawn/transport and SyntheticSource provides the CPU-only workflow. Combining these modules would make the required synthetic and future replay/device paths engine-dependent. | Retain the boundary. There is no removable delegation without losing required isolation. |
| Merge periodic and reliable delivery | stream_broadcaster has one writer but distinct latest-only and reliable inputs. Runner has the corresponding two-channel ownership. Commands, reset recovery and slow-client isolation depend on this distinction. | Retain both delivery policies and the sole pump. A shorter single queue would lose required loss/recovery semantics. |
| Remove native visual fallback groups | Primary external bindings may replace several simultaneous native shapes. The full fallbackVisuals group and collider/placeholder tiers are consumed by the real asset loader and robot/404 browser tests. | Retain. Concatenating or collapsing these layers changes visible geometry and asset failure behavior. |
| Collapse authoritative and interpolated pose state | Inspector/HTTP same-sample checks need exact authority; the renderer intentionally displays delayed interpolated poses and resets the clock after visibility changes. | Retain both with explicit consumers. Relabeling rendered poses with an authoritative seq would invalidate the same-sample acceptance. |
| Remove runtime profiling and debug observations | FrameRecorder is inactive until requested and has bounded storage. The production profile harness records actual loop samples and distinguishes polled source gauges. New instance selection/gather paths still need observable correctness. | Retain the existing public verification seam. Refresh correctness checks and measurement scope for P2-C instead of adding a parallel harness without need. |
| Duplicate scope and reliable-generation state | P2-B removed ClientConnection.stream_ids in favor of its resolved ScopeFilter, and removed reliable-generation tags because reliable FIFO is retained across scope changes. Only the replaceable periodic slot needs generation filtering. | Already simplified and covered by the real blocked-pump/rapid-subscription counterexample. |
| Collapse observed high-water and sample seq | latest_frame/_cache_frame/_apply_state observe a monotonic allocation watermark. A delayed command still has its true older sample seq/simTime; reload allocation must exceed any externally observed frame. | Retain distinct meanings. The real delayed-control HTTP/subscription tests reject both reused allocation and relabeled command metadata. |
| Patch the preceding delta instead of storing a keyframe | Dropped intermediate deltas, returning to baseline, entering/leaving membership and invalid-pose retention need different reconstruction inputs. DeltaBaseline and PoseBuffer have concrete counterexamples for each. | Retain the declared baseline and previous valid pose; neither can substitute for the other. Do not remove membership/entry state merely because pose arrays are already cached. |
| Collapse user hiding, protocol membership and local culling | User hiding persists independently of the camera. Protocol membership governs current pose availability. Local frustum culling changes draw/raycast participation while retaining a complete source sample. Actual mouse, viewport and hidden-parent Site tests distinguish these states. | Retain all three consumer distinctions. LOD changes geometry quality and is separately controlled for comparisons. |
| Compute instance diagnostics from the authoritative pose buffer | InstancedPrimitives reads the actual Float32 instance matrix and removes VisualLocal. A multi-visual opposite-batch counterexample requires a per-Body frame stamp to keep a drawn receipt when another visual is culled. | Retain the matrix observation and stamp. Reading PoseBuffer directly would remove the test's ability to detect a rendering/index-mapping defect. |
| Replace indexed gather mapping with compact row numbers | Runner's _body_targets derives model indices and stream IDs from Manifest identities. The extractor supports reordered targets; the source/renderer stress fixtures use non-contiguous stream IDs. | Retain the explicit mapping. It is required correctness state, not redundant storage. |
| Replace staging/worker ownership with synchronous readback | GPU events, pinned slots and the worker isolate the solver from CPU waiting. Measurements show no single-observation latency win; they do not establish an overlap speedup. | Retain the required ownership model without a speedup claim. Pipe send p95 below0.36ms does not justify a shared-memory subsystem. |
| Early protocol/math formatting debt | The original author sorted imports and wrapped four files. PM independently compared normalized ASTs (only contiguous import order normalized); they match. All eight generated artifact hashes were unchanged in the author check. | Integrated without behavior changes; full Ruff is green. Existing tests and final generation checks cover consumers, with no new mirror tests. |
| Separate decoders for remote periodic, initial and command frames | RemoteSource routes all NSYN through one decoder that validates Manifest membership and stamps actual Gateway receipt time. Remote monotonic clocks cannot be subtracted from Gateway clocks. | Already consolidated. Retain full/subset validation distinctions when the subscription repair extends this path. |
| Collapse local Pipe and remote TLS transports | The local adapter owns spawned process/Pipe cleanup; TLS has certificate identity, authenticated channel pairing, byte/message budgets and finite network deadlines. Both implement SpatialSource for the same Session/HTTP/browser consumers. | Retain separate transport ownership. A generic transport framework would relocate required failure handling without removing obligations. |
| Treat all remote request timeouts as source failure | Joint/mesh queries are read-only; late token responses can be drained. Command timeout leaves mutation outcome unknown. The real client-deadline counterexample returns HTTP504 while advancing frames and a later pause remain valid. | Retain the query/command distinction and the pending-token drain path. Removing it reintroduces session failure after a slow read. |
| Duplicate scene whitelist at Gateway and remote host | Actual stress-100 POST failed at the host while GET/scenes advertised it. Host now lazily reads the same SCENES registry and source combinations before constructing the source. | Duplicate list removed in the integrated repair. A small shared registry module is an optional future extraction, supported by the earlier Standards reviewer; no second whitelist should return. |

| Merge latest partial and complete sample caches | Narrow periodic targets cannot answer an arbitrary new scope or full HTTP recovery. SourceFrames keeps raw source seq/clock, while Session maps global seq on reload and owns the published complete cache. Pose reads that cache without source RPC. | Retain the two completeness guarantees and metadata boundaries. Combining old rows with current rows or relabeling an older sample loses required truth. |
| Repeat barrier/membership logic independently in local and TLS adapters | Both adapters now use SourceFrames for expected IDs, complete authority and seq floors; local Pipe slots and TLS packets still require their own pre-ack handling. | Shared validation removes duplicate semantic maintenance. Retain channel-specific buffering and strict old/new transition validation. |
| Continuously read every Body to serve Pose | Pose is explicitly cache-only. Complete captures occur for explicit snapshot/recovery, interest changes and commands; fixed-scope periodic captures use the active observer union. | Do not restore continuous full readback or add Pose-triggered GPU work. Honest staleMs is part of the retained read model. |
| Treat repeated proxy traffic as a new Runner heartbeat | The producer emits a seq; shared RunnerHeartbeat adds each hop's elapsed receipt age without subtracting host clocks. Duplicate seq cannot rejuvenate age. Synthetic has no marker. | Retain the shared helper and actual producer identity. A proxy's own keepalive cannot replace Runner liveness. |
| Tie Gateway heartbeat lifetime to source tasks | Failed replacement starts must keep API/WS heartbeat alive. One session-owned heartbeat handle persists while the two source monitors stop/restart. | Retain separate ownership, staged candidate commit and cancellation-safe pump cleanup. They replace implicit coupling rather than add a second lifecycle protocol. |
| Revalidate an unchanged PAUSED full snapshot in every host pulse | PM found full membership validation recurring every2ms after a reset. The existing observed-seq guard now includes control snapshots and advances after successful classification. Existing late-query/reset/malformed coverage passes. | Small behavior-preserving reduction implemented by the remote author; no new cache or polling system added. |
| Cache per-capture CUDA index arrays | Current variable-target jobs own their host/device indices until CUDA/event/callback completion. Allocation per capture has a cost; the profiling tool still uses the public capture interface and independent row-order oracle. | Optional performance work requires profiling first. No new speedup follows solely from fewer pose readback bytes; do not add a generic target cache without evidence. |

The issue authors perform bounded simplification before candidate validation. PM's review traces the resulting integrated consumers; optional structural refactors are not added merely to reduce line count. P2-B baseline/scope identity, P2-C gather/index ownership and P2-D connection/failure ownership were inspected. The interest/full-snapshot, cache-only Pose and failed-start repair consumers were inspected through the integrated head. The independent Spec reviewer found no unresolved mandatory finding; Standards and final execution outcomes are recorded in FINAL-REVIEW and the final gate receipt. No additional code cleanup is needed from this survey.
