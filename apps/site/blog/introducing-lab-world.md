# 介绍 Lab World：Agent 的物理工作环境

*更新于 2026 年 10 月 28 日*

![微缩实验室中的机械臂与设备，展示 Agent 参与物理工作的愿景（概念插图）](/images/blog/introducing-lab-world.webp)

Lab World 是我们正在建设的 **Agent 物理工作环境**。它把任务所需的现场状态、行动条件和结果证据组织起来，让 Agent 能在实验室里理解任务、预演流程、执行操作，并判断工作是否真正完成。

比如，在一个指定的观察窗口内完成细胞成像。Agent 需要知道容器里是什么、成像设备是否就绪、机械臂能否安全转移容器，还需要检查图像质量、把容器放回原处，并留下可追溯的记录。模型负责理解与决策，工作环境负责让这些决策有依据、能执行、可验收。

我们的第一站，就是把这样一项边界明确的工作做成完整闭环。在此基础上，再让系统利用失败提出改进，由独立评估检验效果，让通过验证的新版本继续参与下一轮工作。

## 强大的智能，需要能持续工作的环境

Agent 已经能读写代码、调用工具，并根据执行结果调整下一步。在软件工作中，代码库保存共同状态，工具承接行动，测试提供反馈，版本管理保留每次改动。这些条件让复杂任务可以拆分、交接和反复验证。

最近的实践让这种变化更具体。[Bun 团队记录了约 53.5 万行代码从 Zig 向 Rust 的迁移](https://bun.sh/blog/bun-in-rust)：工程师持续监督 Agent，在 11 天内通过约 50 个动态工作流推进实现、审查和测试。已有代码与测试，为长时间运行提供了共同基础。

在生物研究中，[Anthropic 报告了约 950 个 Agent 参与的 DNA 序列搜索](https://www.anthropic.com/research/claude-discovers-novel-enzyme-system)。约 21 小时的搜索产生了值得进一步研究的候选，后续实验由人类科学家完成，所发现系统的自然功能仍在研究。这展示了认知探索可以怎样扩大，也说明实验验证仍是不可缺少的一环。

把同样的能力带进实验室，还缺一层基础设施。仪器可能各有软件，样本信息散在不同记录中，一次操作能否开始、完成后是否合格，仍需要人把它们连接起来。

Lab World 要补上这层环境：让人与 Agent 面对同一份可检查的事实，按明确的条件行动，再用结果证据决定下一步。

## 物理工作需要哪些事实

实验室里，一条指令能否执行，取决于许多会变化的条件：

- **设备状态。** 设备是否忙碌、是否完成校准、读数是什么时候上报的。几分钟前的“就绪”，未必支持现在的动作。
- **样本身份。** 容器的位置、内容与流转记录必须对应，转移过程还要满足样本所需的环境条件。
- **行动前提。** 权限、设备互锁和操作顺序需要在执行时检查。接口返回成功之后，还需要确认预期的物理变化确实发生。
- **结果质量。** 完成采图之后，要判断图像是否符合要求，以及记录是否足够支撑复查。

真实试错会消耗样本、设备时间和人工，有些物理变化无法撤销。因此，状态的可信程度、异常处置和结果验收，都必须成为工作流程的一部分。

## 第一个工作单元：细胞观察与成像

我们首先面向已经具备部分自动化条件的生物技术企业与药企研发团队，选择一个具体目标：**在观察窗口内，交付身份正确、质量合格、记录完整的一次采图。**

这个目标产品的流程包括：

1. 核对容器身份、观察任务与时间要求。
2. 确认成像设备就绪，以及转移路径和相关设备满足行动条件。
3. 转移容器并完成采图。
4. 检查图像质量，按预先定义的规则重试、暂停或交给人处理。
5. 将容器归位，关联图像、设备状态和操作记录。
6. 按验收标准判断本次任务是否完成。

这一流程要交付合格图像，也要留下解释结果的运行记录与质量证据。流程是否完成、图像是否可用、科学假设是否成立，需要分别判断。

它目前是产品切入点和验收目标。实机验证将从替代容器与限定设备开始，逐步增加复杂实验和无菌操作要求。

## 现实出题，虚拟练习，现实验收

Lab World 采用 Real2Sim2Real 的路径，让现实任务决定虚拟环境该练什么。

**现实定义任务。** 从现场提取任务所需的设备、状态与约束，明确什么算成功、哪些异常必须停下。虚拟环境的细节围绕这些要求建立。

**虚拟扩大探索。** 在可重复的场景里预演流程、复现故障、比较策略。例如，主动加入容器偏移、设备忙碌或状态延迟，观察 Agent 在什么条件下会做出错误决定，再围绕弱点安排练习。

**现实裁决结果。** 候选流程或策略经过验证后，在受控条件下迁移到真实设备。现场验收发现的偏差，再带回下一轮虚拟探索。

最早产生价值的，可以是流程顺序和状态检查。随着任务需要，再逐层增加接触、抓取乃至科学过程的真实性。仿真成绩的适用范围要经过现实校准，真实实验始终保留最终验收权。

这一路径已有研究基础。[RialTo](https://arxiv.org/html/2403.03949v3) 利用真实场景的数字孪生，在仿真中改进策略，再回到真实机器人任务中评估。研究展示了特定操控任务上的收益，也为逐项验证虚实迁移提供了方法。

## 平台怎样承接这个闭环

Lab World 的工程基础围绕共同状态、受控行动和运行证据展开。

**人与 Agent 共享状态。** 素材与场景按版本管理，设备的能力、属性和当前状态可以查询。在仿真中，物理源提供唯一的空间事实，浏览器呈现同一份状态。真实设备接入则需要处理现场读数、报告新鲜度与异常。

**动作经过同一条管线。** Web、`lw` 命令行和 MCP 共用 HTTP 动作入口，统一检查参数、前置条件与互锁，并记录执行结果。操作计划列出步骤及预期结果，支持的机械臂动作可在执行前查看路径。

**改动留下可以比较的证据。** 调用、告警、录制和评估记录关联到具体版本，让人和 Agent 能复查失败发生在哪里，以及下一版究竟改了什么。训练、评估与成本管理也围绕这一过程组织。

研究者负责设定目标和验收标准，在训练授权、策略提升、超预算或高风险操作等关口做决定。持续运行还需要补料、维护与异常支持，这些工作同样属于系统的运行条件。

## RSI：让新版本参与下一轮改进

有了执行和反馈，才有条件讨论递归自我改进（Recursive Self-Improvement，RSI）。我们关心的机制是：**当前系统参与提出和验证改进，通过验收的新版本继续执行任务、发现弱点，并参与下一次改进。**

以成像设备未就绪为例。下面是一段目标机制示意：

- **v0 暴露弱点：** Agent 根据已经过时的设备状态，提前把容器取出。
- **提出候选 v1：** Agent 增加“动作前复核状态”的工具或流程，并在状态延迟、设备故障及独立保留任务中验证。
- **v1 继续参与：** 验证通过并获准上线后，新版本继续工作。后续发现的弱点，再成为 v2 的改进依据。

不同失败对应不同层次的改动。状态过时可能需要改工具和流程，抓取不稳可能需要调整训练数据或控制策略。平台因此支持两类改进对象：

| 改进层次 | 可以改变什么 | 怎样判断效果 |
| --- | --- | --- |
| Agent 层 | 技能、指令、工具及运行配置，基础模型保持固定 | 比较固定任务上的表现、失败与成本 |
| 具身层 | 控制策略、设备程序、奖励与示范数据 | 在固定本体和场景条件下评估，再做受控实机验收 |

日志和记忆为改进提供材料。是否形成 RSI，还要看系统有没有产生经过验证的新版本，以及新版本是否继续参与改进。评估标准与关键安全规则需要独立于被评估的系统，候选版本也必须满足接受规则、预算与人工审批要求。

## 一次实验，可以推动两种进步

在我们希望建立的系统里，实验结果进入两个相互关联的闭环。

**科学闭环增加对世界的认识。** 研究者提出关于细胞状态、培养条件或材料性能的假设，通过实验与测量获得证据，再修正假设。

**能力闭环改进工作的方式。** 系统发现操作中的弱点，提出工具、流程或策略候选，经过独立评估与必要的真实验收，形成下一版执行能力。

一张合格图像可以为科学问题提供数据，一次设备等待失败则可以暴露调度方法的缺陷。两者分别有自己的评价标准，也都能为下一轮工作提供更好的起点。

## 连续运行与经验复用的价值

实验室扩大产出的机会，来自减少无人值守时段的空转，让多个工作单元在运行条件允许时并行推进。生物生长和反应过程仍有自身的时间尺度，维护、补料、质控和异常处理也需要计入可用时间。

另一种积累来自真实运行经验。设备接入时的协议和校准要求、失败发生的条件、异常恢复方法、图像质量基线，以及虚拟与现实之间的偏差，都可以成为下一次部署的依据。

我们希望这些经验逐步形成带版本、适用条件和验证证据的能力资产，让下一座实验室少做重复工程。跨站复用仍须重新确认设备和任务条件，并区分客户私有数据、获授权的衍生成果与通用方法。

## 今天走到了哪一步

截至 2026 年 10 月 28 日，Lab World 已交付的范围是**平台工程与本地演示工作台**：

- **虚拟工作环境：** 素材与场景库、物理状态同步、统一动作管线、操作计划、路径预览、告警、历史与录制回放。
- **训练与改进的工程流程：** 训练作业管理、策略和脚本产物、平台内评估、版本提升与回滚，以及 Agent 运行记录和成本管理。已有局部运行验证。
- **仍待验证的能力：** 学习得到的接触抓取策略可靠性、完整真实模型评估，以及经过独立验证的持续自主改进。工程流程已经接通的部分，仍需要这些质量证据。
- **真实业务闭环：** 设备接入基础已有实现，细胞观察与成像工作单元的实机闭环、长期运行质量和多站复制仍是后续验证目标。

这些进展说明我们已经有了开展验证的工作台。真实实验室的持续交付能力，还需要在现场逐项建立。

## 接下来，按证据扩大自主性

接下来的路线围绕清晰的验收点推进：先验证虚拟环境中的状态一致性和异常处理，再完成限定设备下的成像工作单元，积累真实质量与恢复记录。单个工作单元稳定之后，才有依据扩大任务范围、复制到更多站点，并验证受控能力改进。

实验室是起点。长期来看，同样的方法可以服务相邻实验、检测、材料测试与精密测量：研究者设定方向和验收标准，Agent 在具备运行条件的物理环境里持续工作，并把经过验证的经验带进下一次任务。
