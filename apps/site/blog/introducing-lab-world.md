# 介绍 Lab World：让实验室学会自我改进

![夜色中的一座微缩实验室，机械臂在工作，上方一道靛蓝色的光盘旋上升](/images/blog/introducing-lab-world.webp)

我们在做一个实验室平台，叫 Lab World。它要做的事说起来很简单：你给它一个目标，agent 自己设计实验流程、操控机器人与设备、从失败中训练新的策略，直到拿到结果；再把学到的东西带到下一座实验室。

这篇文章讲三件事：为什么递归自我改进（RSI）现在可以动手做；为什么它必须进入实验室；以及 Lab World 打算怎样把这个闭环搭起来。

## 一个六十年前的想法

1965 年，数学家 I. J. Good 在《Speculations Concerning the First Ultraintelligent Machine》里提出了「智能爆炸」。他的论证只有一步：设计机器本身是一种智力活动，所以一台在所有智力活动上都超过人的机器，也能设计出比自己更好的机器；后者再设计出更好的，智能就这样递归地增长下去。他写道：

> 第一台超智能机器，将是人类需要做出的最后一项发明。

此后几十年，这个想法一直停在思想实验里。没有哪个系统真的能改进自己，更谈不上递归。

## 为什么是现在

变化来自大模型 agent。今天的 agent 能读写代码、调用工具、连续工作数小时，还能根据结果修改自己的指令、技能和工具配置。这让 RSI 第一次可以写成一个具体的循环：

1. 找到自己的一个组成部分，比如一段指令、一个技能、一份机器人策略；
2. 提出一个改动；
3. 用反馈判断改动是好是坏；
4. 只保留更好的版本，然后进入下一轮。

与 RSI 有关的研究正在快速增长，从 agent 改写自己的提示和技能，到 coding agent 在仿真里为机器人写程序、做训练。我们关心的是其中最朴素的一个问题：第 3 步的反馈从哪里来？

## 反馈必须来自外部

一个只和自己对话的系统，学不到它原本不知道的东西。自我改进要持续下去，就需要来自外部世界的信号。

在软件里，这个信号来自测试、基准和用户。在科学里，它只有一个来源：实验。一个关于细胞生长、材料配方或机器人抓取的假设对不对，最终只能由真实的物理世界回答。

所以我们认为，RSI 要走出屏幕，就必须进入实验室。实验室是自我改进与真实世界接触的地方。

## 实验室今天缺什么

实验室里不缺机器人和仪器，缺的是让 agent 看得懂、动得了、学得会的那一层：

- **设备是黑箱。** 每台仪器一套软件和协议，agent 不知道它能做什么、此刻处于什么状态。
- **流程靠人。** 实验脚本由人写、由人盯着跑，出了问题也由人判断。
- **失败没有被记下来。** 哪一步失败、为什么失败，常常只留在操作员的记忆里。
- **改进要请专家。** 机器人某个动作的成功率不够，就要重新示教、重新调参。

## Lab World 怎么做

Lab World 从最底层开始，把实验室变成 agent 可以操作、也可以从中学习的地方。

**一个事实源。** 物理源（Newton，或不需要 GPU 的 Synthetic）是唯一的事实。每台设备是什么类型、能做什么、此刻读数如何，人和 agent 读到的是同一份。

**一条动作管线。** Web、`lw` 命令行和 MCP 走同一条管线：校验参数、检查前置条件与互锁、执行、记录。agent 没有后门；危险动作会被拦下，高风险动作要人批准。

**先计划，再动手。** agent 把目标拆成操作计划，每一步写明要做什么、期望看到什么。机械臂要走的路径，在动手之前就能预演。

**每一步都可以回看。** 调用、读数、告警和录制都会保存下来，agent 可以回看任意一次运行，找到瓶颈在哪里。

## 两层自我改进

在这些基础之上，Lab World 用同一套框架改进两类对象：

| | Agent 层 | 具身层 |
| --- | --- | --- |
| 改进对象 | 操作实验室的 agent | 驱动机器人的 Controller |
| 保持不变 | 模型与思考等级 | 机器人本体与场景版本 |
| 可以改 | 平台 skill、指令、工具与 MCP 配置 | 策略、设备程序、奖励、示范数据 |
| 评估 | 实验室操作任务 | 机器人回合 |
| 成本 | LLM Token | GPU 小时 |

每一轮都是：一个可证伪的假设，一处有边界的改动，在评估集上评估，满足接受规则才成为新版本。

## 什么样的改进才算数

自我改进最大的风险，是把「看起来更好」当成「真的更好」。所以我们给改进定了几条硬规则：

- **接受规则是统计意义上的。** 具身层要求候选版本成功率的 Wilson 95% 置信区间下界，高于当前版本的成功率；agent 层要求训练题平均分严格更高，每题至少运行 3 次。
- **改进者看不到考题。** 负责改进的 Optimizer 读不到私有评分条件和测试集。每次工具调用都留在 Trace 里；一旦发现泄露，候选回滚，这一轮计划标记为污染。
- **每一轮都有成本。** Token、GPU 小时和耗时都记进成本中心，闭环有预算上限。

## 人在哪里

Lab World 想让人只需要给出目标，但人并没有离开。闭环里有几道只有人能通过的关口：批准训练计划、把新策略提升为默认、超预算运行、删除库里的版本。它们不需要人盯着每一步，只在真正需要判断的时候，请人点一下。

## 今天走到了哪一步

我们会把每一块的真实状态写清楚：

- **已交付：** 单一物理源同步到浏览器；Web、`lw` 与 MCP 共用一条动作管线；素材库与场景库；传感器、告警、历史与 agent 收件箱（仿真设备）；操作计划与机械臂路径预览；教 agent 使用平台的平台 skill。
- **进行中：** 计划页界面；`fr3-lab` 场景导入与抓取验证；真实设备通过 Device Host 与 MQTT 接入。
- **规划中：** 训练作业、训练视图与平台内评估；两层 RSI、评估中心与成本中心。
- **愿景：** 由目标驱动的长程自主实验；在实验室之间共享的能力库。

## 接下来

下一步是把训练接进平台：agent 起草训练计划，在并行仿真里训练机器人策略，用评估集打分，过线之后由人批准、接回设备程序。这是闭环里最关键的一环，也是从「agent 操作实验室」走向「实验室自我改进」的分界线。

我们相信，当一座实验室能够自己变好，下一步就不再是一座实验室，而是一千座。我们会在这里持续记录这条路上的进展。
